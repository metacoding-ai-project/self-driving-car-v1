### 다른 방법이 있다고?

v5까지의 여정이 끝난 어느 날이었습니다. 메타코딩은 퇴근 준비를 하다가 김선배를 마주쳤습니다.

"메타코딩 씨, 잘했어요. 73%까지 올리다니."

김선배가 커피잔을 들며 말했습니다.

"감사합니다. 그런데 90%까지는 아직 갈 길이 멀어요."

메타코딩이 한숨을 쉬었습니다. 5주 동안 v0부터 v5까지, 규칙 기반에서 DQN까지 달려왔는데 아직도 27%가 남아 있다니.

김선배가 갑자기 물었습니다.

**"그런데 DQN 말고 다른 방법으로도 자율주행을 만들 수 있는 거 알아요?"**

"네? 다른 방법이요?"

"DQN은 신경망으로 복잡한 계산을 하잖아요. 근데 **'질문'만으로 판단하는 AI**도 있어요. 훨씬 간단하고, 왜 그렇게 판단했는지 사람이 이해할 수도 있어요."

메타코딩의 눈이 동그래졌습니다.

"질문만으로요? 그게 가능해요?"

김선배가 웃으며 노트를 꺼냈습니다.

"**의사결정 트리**라는 거예요. 그리고 그 트리를 100개 모으면 **랜덤 포레스트**가 되고요. 심지어 정답 없이 스스로 분류하는 **K-Means**라는 것도 있어요."

메타코딩은 노트에 적기 시작했습니다.

> _"DQN만이 정답은 아니다. 같은 문제를 다른 각도에서 풀어보자!"_

### 먼저, 데이터를 모으자!

의사결정 트리와 랜덤 포레스트는 **지도학습** 방식입니다. 프롤로그에서 배운 것, 기억나시나요?

```
AI가 배우는 3가지 방식 (프롤로그 복습!):

1. 지도학습: "정답을 알려주고 배우기"

2. 비지도학습: "정답 없이 패턴 찾기"

3. 강화학습: "시행착오로 배우기"
   → 보상과 패널티로 스스로 학습 ← DQN이 이거였죠!
```

지도학습은 **"문제와 정답이 세트로 있어야"** 합니다. 그런데 자율주행에서 정답을 어디서 구하죠?

## 의사결정 트리: "질문"으로 판단하는 AI

### 핵심 아이디어

의사결정 트리는 이름 그대로, **나무 모양의 질문**을 던져서 답을 찾아가는 AI입니다.

우리가 일상에서 하는 판단도 사실 이런 구조입니다. "오늘 우산을 가져갈까?"를 생각해보세요.

```
[일상 속 의사결정 트리]

          "하늘에 구름이 많나?"
              /         \
           Yes           No
            |             |
     "비 확률 50% 이상?"   "우산 안 가져감!"
         /        \
       Yes        No
        |          |
  "우산 가져감!"  "접이식 우산만"
```

자율주행 AI도 똑같습니다!

```
[자율주행 의사결정 트리]

              "앞에 벽이 있나?"
                /          \
              Yes           No
               |             |
     "목적지가 오른쪽?"    "목적지 방향으로"
         /        \          → 직진!
       Yes        No
        |          |
   "우회전!"    "좌회전!"
```

DQN은 숫자 수천 개를 곱하고 더하는 복잡한 계산으로 판단하지만, 의사결정 트리는 **질문과 대답만으로** 판단합니다. 마치 스무고개 게임처럼요!

> 🎨 **이 그림을 더 예쁘게 보고 싶다면?** 아래 프롬프트를 Gemini에게 보내보세요!
>
> *프롬프트: "자율주행 자동차의 의사결정 트리(Decision Tree) 다이어그램을 그려줘. 맨 위 루트 노드에 '앞에 벽이 있나?'가 있고, Yes로 가면 '목적지가 오른쪽인가?', No로 가면 '직진!'으로 연결돼. '목적지가 오른쪽인가?'에서 Yes는 '우회전!', No는 '좌회전!'으로 이어져. 나무(tree) 모양으로, 각 노드를 둥근 사각형으로, 최종 결정(잎)은 초록색으로 강조해줘. 깔끔한 인포그래픽 스타일, 한국어 라벨 포함."*

### 트리가 자율주행을 배우는 과정

`train_tree.py`를 실행하면, 트리는 수집된 데이터를 보면서 **스스로 질문을 만들어** 갑니다.

```python
# train_tree.py 핵심 부분

# 의사결정 트리 학습!
tree = DecisionTreeClassifier(max_depth=10, random_state=42)
tree.fit(X_train, y_train)    # 데이터를 보면서 질문을 만든다!
```

`max_depth=10`은 "질문을 10번까지만 해라"라는 뜻입니다. 질문을 너무 많이 하면 과적합에 빠지거든요. v3에서 배운 것처럼요!

학습이 끝나면, 트리는 자동으로 **"어떤 정보가 가장 중요한지"**를 알려줍니다. 이것이 바로 **Feature Importance(특성 중요도)** 입니다.

```
트리가 가장 중요하게 보는 정보:

  1. 목적지Y 방향 : 0.312  ★★★★★
  2. 목적지X 방향 : 0.278  ★★★★
  3. 위 벽         : 0.145  ★★★
  4. 아래 벽       : 0.089  ★★
  5. 현재 방향     : 0.076  ★

→ "목적지가 어디인지"가 가장 중요하고,
   "바로 앞에 벽이 있는지"가 그 다음으로 중요하다!
```

이게 바로 의사결정 트리의 최대 장점입니다. **"왜 그렇게 판단했는지 사람이 이해할 수 있다!"** 이걸 AI에서는 **"해석 가능성(Interpretability)"**이라고 부릅니다.

DQN은 어떤가요? 신경망 안에 숫자가 수천 개 들어있는데, 왜 직진을 선택했는지 사람이 들여다봐도 도무지 이해할 수 없습니다. 그냥 "컴퓨터가 계산했대"가 전부예요. 마치 블랙박스처럼요.

하지만 트리는 다릅니다:

```
DQN (블랙박스):
  입력 → [????복잡한 계산????] → "직진!"
  사람: "왜 직진이야?"
  DQN: "......(수천 개 숫자를 보여줌)"
  사람: "무슨 소리야?"

의사결정 트리 (해석 가능!):
  "앞에 벽? No → 목적지가 오른쪽? No → 직진!"
  사람: "아, 앞에 벽이 없고 목적지가 앞쪽이니까 직진이구나!"
  사람: "이해가 돼!"
```

> 💡 **어렵게 느껴지면 이것만 기억하세요!**
> - 의사결정 트리 = **"스무고개 게임"** 하듯이 질문을 던져서 답을 찾는 AI
> - 최대 장점 = **왜 그렇게 판단했는지 사람이 이해할 수 있음!** (해석 가능성)
> - 최대 단점 = 복잡한 상황에서 **DQN보다 성능이 낮음**

## 랜덤 포레스트: 100개 트리의 "투표"

### 핵심 아이디어

혼자 판단하면 틀릴 수 있지만, **100명이 투표하면** 정답에 가까워집니다.

이걸 AI에서는 **앙상블(Ensemble)**이라고 부릅니다.

```
[앙상블의 원리 — 투표!]

트리 1호:  "직진!"
트리 2호:  "직진!"
트리 3호:  "우회전!"
트리 4호:  "직진!"
트리 5호:  "직진!"
   ...
트리 99호: "직진!"
트리 100호: "직진!"

투표 결과: 직진 80표 / 우회전 15표 / 좌회전 5표
       → "직진!"
```

학교에서 반장 선거를 하는 것과 비슷합니다. 한 명의 의견보다 30명의 투표가 더 공정하고 정확하죠?

그런데 여기서 중요한 점이 있습니다. 트리 100개를 **똑같이** 만들면 의미가 없어요. 같은 사람 100명에게 물어보는 것과 같으니까요. 그래서 랜덤 포레스트는 각 트리를 만들 때 **다른 데이터, 다른 질문**을 사용합니다.

```
왜 "랜덤" 포레스트인가?

트리 1호: 데이터 70%를 랜덤으로 뽑아서 학습
          + 질문할 때 사용할 정보도 랜덤으로 선택
트리 2호: 다른 70%를 뽑아서 학습
          + 다른 정보를 랜덤으로 선택
트리 3호: 또 다른 70%를...
   ...
트리 100호: 또 다른 조합으로!

→ 100개 트리가 각자 다른 관점에서 판단!
→ 투표하면 편향된 판단이 상쇄됨!
```

비유하면 이렇습니다. 시험 범위가 100페이지인데, 학생 A는 1~70페이지를 공부하고, 학생 B는 20~90페이지를 공부하고, 학생 C는 30~100페이지를 공부했어요. 혼자서는 모르는 범위가 있지만, 셋이 모여서 답을 맞춰보면 거의 모든 범위를 커버할 수 있죠!

### 코드로 보면

```python
# train_forest.py 핵심 부분

# 랜덤 포레스트 학습! (트리 100개!)
forest = RandomForestClassifier(
    n_estimators=100,    # 트리 100개!
    max_depth=10,        # 각 트리는 질문 10번까지
    random_state=42
)
forest.fit(X_train, y_train)
```

`n_estimators=100`이 "트리 100개를 만들어라"라는 뜻입니다. 이 한 줄이 앙상블의 핵심이에요!

`train_forest.py`를 실행하면, 단일 트리와 랜덤 포레스트의 성능을 자동으로 비교해줍니다.

```
앙상블 효과 비교:
  트리 1개 정확도:          약 85%
  트리 100개(포레스트) 정확도: 약 89%
  → 포레스트가 약 4% 더 정확! (투표의 힘!)
```

> 💡 **어렵게 느껴지면 이것만 기억하세요!**
> - 랜덤 포레스트 = **트리 100개가 투표해서 결정!**
> - 왜 더 좋은가? = 한 명이 틀려도 다수가 보정해줌
> - 핵심: **다양한 관점의 조합 > 한 명의 천재**

## K-Means 클러스터링: 정답 없이 스스로 분류하는 AI!

### 이건 비지도학습!

의사결정 트리와 랜덤 포레스트는 **정답이 있었습니다.** DQN이 만들어준 "이 상황에서는 직진!"이라는 답안지를 보고 배웠죠. 이것이 **지도학습**입니다.

하지만 K-Means는 다릅니다. **정답이 없어도** AI가 스스로 패턴을 찾아냅니다!

프롤로그에서 배운 **비지도학습**, 기억나시나요? 선생님 없이 혼자서 패턴을 발견하는 것. K-Means가 바로 그겁니다.

### K-Means가 하는 일

우리 시뮬레이터에는 맵이 20개 있습니다. 어떤 맵은 쉽고, 어떤 맵은 어렵죠. 하지만 지금까지 "이 맵은 쉬워", "이 맵은 어려워"라고 **누가 알려준 적이 없습니다.**

K-Means는 맵의 특성(벽 비율, 거리, 난이도)만 보고 **스스로** "비슷한 맵끼리" 묶어줍니다!

```
K-Means에게 맵 정보를 주면:

맵 특성 (3가지 숫자):
  [벽 비율, 시작↔목적지 거리, 목적지 주변 벽 밀도]

맵 0:  [0.15, 0.20, 0.12]  ← 벽 적고, 거리 가깝고
맵 3:  [0.35, 0.45, 0.40]  ← 중간 정도
맵 7:  [0.50, 0.65, 0.55]  ← 벽 많고, 거리 멀고
맵 12: [0.12, 0.18, 0.10]  ← 벽 적고, 거리 가깝고
...
```

K=3으로 설정하면, K-Means는 이 맵들을 **3개 그룹**으로 나눕니다.

```
K-Means 분류 결과:

  그룹 쉬움 🟢 : 맵 [0, 2, 5, 12, 15]
    → 벽 적고, 거리 가까움

  그룹 보통 🟡 : 맵 [1, 3, 8, 10, 14, 17]
    → 중간 난이도

  그룹 어려움 🔴 : 맵 [4, 6, 7, 9, 11, 13, 16, 18, 19]
    → 벽 많고, 거리 멀고, 목적지 도달이 까다로움

→ 아무도 알려주지 않았는데 스스로 분류했다!
```

여기서 "K=3"의 K는 그룹 개수입니다. K=3이면 3개 그룹, K=5이면 5개 그룹으로 나눕니다.

### 커리큘럼 러닝: 쉬운 것부터!

이 분류 결과를 어디에 쓸 수 있을까요?

사람도 공부할 때 **쉬운 문제부터** 풀잖아요. 갑자기 수능 문제를 주면 포기하지만, 기초 문제 → 중급 문제 → 고급 문제 순서로 풀면 실력이 쑥쑥 오릅니다.

AI도 마찬가지입니다!

```
커리큘럼 러닝 (Curriculum Learning):

1단계: 쉬운 맵 🟢 으로 학습
  → AI가 기본기를 익힘 ("벽을 피하는 법")

2단계: 보통 맵 🟡 으로 학습
  → AI가 응용력을 키움 ("복잡한 길에서도 판단")

3단계: 어려운 맵 🔴 으로 학습
  → AI가 고급 능력을 발휘 ("극한 미로에서도 탈출!")

비유: 수학 공부
  1단계: 1+1 = 2 (기초)
  2단계: 23 × 45 = ? (응용)
  3단계: 미적분 (심화)
  → 처음부터 미적분을 배우면? 포기!
```

K-Means가 맵을 자동으로 난이도별로 분류해주니까, 이 순서대로 DQN을 학습시키면 **더 효율적으로** 배울 수 있습니다!

## CNN 개념 소개: 이미지로 보는 AI

> **이 섹션은 개념만 소개합니다. 실제 코드는 없습니다!**

김선배가 시뮬레이터 화면을 가리키며 말했습니다.

"지금 AI가 보는 건 뭐였죠?"

"11개 숫자요. 주변 8칸 벽 정보, 방향, 목적지 x, y."

"맞아요. 근데 우리 **눈으로** 화면을 보면 어때요? 전체 맵이 한눈에 보이잖아요. 벽이 어디 있는지, 통로가 어떻게 이어지는지. 만약 AI도 **이미지**로 볼 수 있다면?"

이것이 바로 **CNN(Convolutional Neural Network, 합성곱 신경망)** 의 아이디어입니다.

### 현재 AI vs CNN

```
현재 AI (DQN):
  "나 주변 한 칸만 봐요"
  → 11개 숫자 [0,1,0,0,0,1,0,0,1,+0.6,+0.4]

CNN:
  "맵 전체를 사진처럼 봐요"
  → 30×30 = 900개 숫자 (이미지!)

  ██████████████████
  █ 🚗            █
  █   ████  ████  █     ← CNN은 이 그림 전체를
  █                █       한 장의 사진으로 봄!
  █   ████    🟩   █
  ██████████████████
```

### CNN은 어떻게 이미지를 이해할까?

핵심은 **필터(Filter)**입니다.

```
[1단계: 필터로 이미지 훑기]

3×3 크기의 작은 창문(필터)이 이미지 위를 슬라이딩하며
"여기에 벽이 있나?", "여기에 통로가 있나?"를 감지합니다.

이미지:               필터 (3×3):          결과:
████████████         ┌─────┐
█          █         │1 1 1│       "벽 발견!"
█  ████    █    ×    │0 0 0│   →   "통로 발견!"
█          █         │0 0 0│       "빈 공간!"
████████████         └─────┘

→ 필터가 이미지 전체를 훑으면서 특징을 찾아냄!
→ 벽 찾는 필터, 통로 찾는 필터, 모서리 찾는 필터... 여러 개!
```

```
[2단계: 풀링(Pooling)으로 핵심만 남기기]

30×30 → 15×15 → 7×7 으로 점점 줄이면서
중요한 정보만 남김!

비유: 책 요약하기
  원본: 300페이지 소설
  1차 요약: 30페이지 줄거리
  2차 요약: 3페이지 핵심 요약
  → 핵심만 남았지만, 이야기의 본질은 유지!
```

```
[3단계: 최종 판단]

추출한 특징들을 모아서 "직진? 우회전? 좌회전?" 결정!

이미지 → 필터(특징 추출) → 풀링(축소) → 판단(직진!)
```

### 왜 우리 시뮬레이터에서 안 쓰나요?

```
지금 AI:  11개 숫자 → 신경망(78개 뉴런) → 판단
          → 빠르고 간단!

CNN:     900개 숫자 → 필터 수십 개 → 풀링 → 판단
          → 훨씬 강력하지만, 학습이 수십 배 오래 걸림!
```

지금 시뮬레이터에서는 11개 숫자만으로도 73%를 달성했으니, 굳이 CNN을 쓸 필요가 없습니다. 하지만 **실제 자율주행 자동차**에서는? 카메라로 찍은 진짜 도로 이미지를 봐야 하니까 CNN이 필수입니다!

> 💡 **어렵게 느껴지면 이것만 기억하세요!**
> - CNN = **이미지를 이해하는 AI**
> - 핵심: 작은 필터가 이미지를 훑으면서 **"벽!", "통로!", "모서리!"** 같은 특징을 찾아냄
> - 우리 시뮬레이터: 숫자 11개로 충분 / 실제 자율주행: 카메라 이미지 → CNN 필수!

>
> *프롬프트: "CNN(Convolutional Neural Network) 자율주행 적용 다이어그램을 그려줘. 왼쪽에 30x30 격자 맵 이미지(벽은 빨간색, 통로는 흰색, 자동차는 파란색). 화살표 다음에 3x3 필터가 이미지를 훑는 모습. 그 다음 풀링으로 크기가 줄어드는 과정(30x30→15x15→7x7). 마지막에 '직진! / 우회전! / 좌회전!' 출력. 각 단계 아래에 한국어로 '특징 추출', '핵심만 남기기', '판단' 라벨. 깔끔한 인포그래픽 스타일."*

## LSTM/RNN 개념 소개: 기억하는 AI

> **이 섹션도 개념만 소개합니다. 실제 코드는 없습니다!**

메타코딩이 시뮬레이터를 보다가 말했습니다.

"김선배님, 자동차가 같은 곳을 왔다 갔다 할 때가 있어요. '아까 거기 갔는데 막다른 길이었잖아'를 기억하면 안 가겠죠?"

김선배가 고개를 끄덕였습니다.

"맞아요. 지금 AI는 **현재 이 순간만** 보고 판단해요. 1초 전에 어디 있었는지 기억을 못 하죠. 근데 **과거를 기억하는 신경망**이 있어요."

### 일반 신경망 vs RNN vs LSTM

```
일반 신경망 (우리 DQN):
  "지금" 만 봄
  ┌──────┐     ┌──────┐     ┌──────┐
  │ t=1  │     │ t=2  │     │ t=3  │
  │상태→판단│   │상태→판단│   │상태→판단│
  └──────┘     └──────┘     └──────┘
      ↑            ↑            ↑
  각각 독립!    이전을 모름!   이전을 모름!

RNN (순환 신경망):
  "과거도 기억"함
  ┌──────┐     ┌──────┐     ┌──────┐
  │ t=1  │────▶│ t=2  │────▶│ t=3  │
  │상태→판단│   │상태+기억│   │상태+기억│
  └──────┘  기억 └──────┘ 기억 └──────┘
              전달!          전달!

  t=3에서 판단할 때:
  "t=1에서 왼쪽으로 갔고, t=2에서 벽이었어.
   그러니까 t=3에서는 오른쪽으로 가야 해!"
```

하지만 RNN에는 약점이 있습니다. 기억이 **점점 흐려진다**는 것이에요. 마치 전화기 게임처럼, 사람을 거칠수록 원래 메시지가 왜곡되는 것과 같습니다. 10걸음 전의 기억은 거의 사라져요.

그래서 나온 것이 **LSTM(Long Short-Term Memory, 장단기 기억)** 입니다.

```
LSTM의 핵심: "무엇을 기억하고, 무엇을 잊을지 선택!"

일반 기억 (RNN):
  1걸음 전 ★★★★★  (선명!)
  3걸음 전 ★★★     (흐릿...)
  5걸음 전 ★        (거의 안 보임)
  10걸음 전 ☆       (사라짐!)

LSTM:
  "이건 중요해! 오래 기억하자!"
  → 10걸음 전 갈림길 ★★★★  (아직 기억!)

  "이건 별로야, 잊어도 돼."
  → 3걸음 전 빈 통로   ☆    (버림)

비유: 시험 공부
  일반 기억 = 어제 공부한 건 기억, 일주일 전은 잊음
  LSTM = 중요한 공식은 일주일 전 거도 기억,
         사소한 건 어제 거도 잊음
```

### 자율주행에 적용하면?

```
LSTM 자율주행:

시점 t=1: "앞으로 직진!" (별다른 정보 없음)
시점 t=5: "오른쪽에 갈림길 발견!" → 기억에 저장!
시점 t=10: "막다른 길이다!"
시점 t=11: "아까 t=5에서 갈림길이 있었지?
           그쪽으로 돌아가자!" ← LSTM이 기억해줌!

일반 DQN이라면:
시점 t=11: "막다른 길이다... 어디로 가지?"
           (갈림길? 기억 안 남...)
```

> 💡 **어렵게 느껴지면 이것만 기억하세요!**
> - RNN = **과거를 기억하는 AI** (하지만 오래된 기억은 잊음)
> - LSTM = RNN의 업그레이드. **중요한 기억은 오래, 사소한 기억은 버림!**
> - 자율주행 예: "이 길은 아까 와본 곳이야, 다른 길로 가자!"

> 🎨 **이 그림을 더 예쁘게 보고 싶다면?** 아래 프롬프트를 Gemini에게 보내보세요!
>
> *프롬프트: "RNN과 LSTM의 차이를 자율주행 자동차에 비유한 다이어그램을 그려줘. 위쪽에 일반 신경망: 자동차가 매 순간 독립적으로 판단(기억 없음). 가운데에 RNN: 자동차가 이전 기억을 다음 단계로 전달(화살표로 연결), 하지만 멀리 갈수록 기억이 흐려짐(색이 옅어짐). 아래쪽에 LSTM: 자동차가 '중요한 기억(갈림길)'은 선명하게 유지하고 '사소한 기억(빈 통로)'은 버리는 모습. 깔끔한 인포그래픽 스타일, 한국어 라벨 포함."*

"우리 AI의 신경망, 은닉층이 몇 개였죠?"

"1개요. 뉴런 64개짜리."

"맞아요. 1화에서 배운 것처럼, 입력층 → 은닉층 1개 → 출력층. 그런데 만약 은닉층을 **여러 개** 쌓으면 어떻게 될까요?"

```
우리 AI (얕은 신경망):
  입력(11개) → 은닉층 1개(64뉴런) → 출력(3개)

더 깊은 AI:
  입력 → 은닉층 1 → 은닉층 2 → 은닉층 3 → 출력

아주 깊은 AI:
  입력 → 은닉층 1 → 은닉층 2 → ... → 은닉층 100 → 출력
```

이렇게 은닉층을 여러 개 쌓는 것이 바로 **"딥(Deep)"러닝**입니다!

"1화에서 배운 '신경망'에 '깊이'를 더한 것이에요."

### 왜 깊으면 좋을까?

각 층이 점점 더 **복잡한 개념**을 이해하기 때문입니다.

```
자율주행 예시:

1층 (기초):
  "바로 앞에 벽이 있나?"
  "바로 옆에 벽이 있나?"
  → 단순한 감지!

2층 (조합):
  "앞이랑 옆이 다 벽이면 → 막다른 길이구나!"
  "앞이 뚫리고 옆도 뚫려있으면 → 갈림길이구나!"
  → 1층의 정보를 조합해서 상황을 파악!

3층 (판단):
  "막다른 길인데 뒤로 돌아가면 우회로가 있을까?"
  "이 갈림길에서 어느 쪽이 목적지에 가까울까?"
  → 2층의 상황 파악을 바탕으로 전략적 판단!
```

실생활로 비유하면 이렇습니다:

```
사진 인식 예시 (얼굴 인식):

1층: "밝은 점? 어두운 점?" (픽셀 수준)
2층: "선이 있네! 곡선이 있네!" (윤곽)
3층: "이건 눈이구나! 이건 코구나!" (부분)
4층: "이건 사람 얼굴이다!" (전체)

→ 층이 깊어질수록, 단순한 정보 → 복잡한 개념으로!
→ 이게 바로 "딥(Deep)"러닝의 핵심!
```

"그런데 무작정 깊게 쌓으면 좋은 건 아니에요." 김선배가 덧붙였습니다.

```
층이 너무 깊으면:
  - 학습이 매우 오래 걸림
  - 기울기 소실: 맨 뒤의 수정 신호가 앞까지 전달이 안 됨
    (전화기 게임처럼 중간에 메시지가 사라짐!)
  - 데이터가 적으면 과적합 (v1에서 배운 것!)

→ 적절한 깊이를 찾는 것이 중요!
→ 우리 AI는 은닉층 1~2개면 충분!
```

> 💡 **어렵게 느껴지면 이것만 기억하세요!**
> - 딥러닝 = **은닉층을 여러 개 쌓은 신경망**
> - 층이 깊을수록 = **더 복잡한 패턴**을 이해할 수 있음
> - 1층: "벽이 있나?" → 2층: "막다른 길인가?" → 3층: "우회로가 있나?"
> - 이게 바로 **"딥(Deep)"러닝**이라는 이름의 이유!

### 번외편을 마치며

메타코딩은 노트를 덮으며 생각했습니다.

'DQN만 알았을 때는 망치 하나만 들고 있었는데, 이제 드라이버도, 렌치도, 톱도 생겼다.'

세상에는 DQN만 있는 것이 아닙니다. 의사결정 트리처럼 간단하지만 설명 가능한 AI도 있고, 랜덤 포레스트처럼 여럿의 힘을 모으는 AI도 있고, K-Means처럼 정답 없이 패턴을 찾는 AI도 있습니다.

그리고 CNN처럼 이미지를 보는 AI, LSTM처럼 과거를 기억하는 AI도 있습니다. 아직 직접 만들어보진 못했지만, **"이런 게 있다"**를 아는 것만으로도 큰 차이입니다.

문제가 생겼을 때 "DQN으로 풀어야지"가 아니라, **"이 문제에는 어떤 AI가 적합할까?"**를 고민할 수 있게 된 것이니까요.

> _문제에 맞는 알고리즘을 고를 줄 아는 사람이다._
