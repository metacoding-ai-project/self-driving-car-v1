## 시작하기 전에: 실습 환경 준비

이 책은 **이론서이자 실습서**입니다! 각 화마다 직접 시뮬레이터를 실행해보며 AI가 학습하는 과정을 눈으로 확인할 수 있습니다. 아래 순서대로 환경을 준비해주세요.

### 1단계: 파이썬(Python) 설치

AI 시뮬레이터는 파이썬으로 만들어져 있습니다. 파이썬이 설치되어 있지 않다면 아래 링크에서 다운로드해주세요.

- **다운로드:** https://www.python.org/downloads/
- **버전:** Python 3.8 이상 권장
- 설치 시 **"Add Python to PATH"** 체크박스를 반드시 체크해주세요!

설치 확인:
```bash
python --version
# Python 3.x.x 가 나오면 성공!
```

### 2단계: 커서(Cursor) 설치 + 파이썬 익스텐션

코드를 편하게 보고 실행하려면 **커서(Cursor)** 에디터를 추천합니다.

- 설치 후 **Extensions(확장)** 탭에서 **"Python"** 을 검색하여 설치해주세요.
- Python 익스텐션이 있어야 코드 자동완성, 실행 등이 편리합니다.

### 3단계: GitHub에서 프로젝트 다운로드

이 책의 모든 실습 코드는 아래 GitHub 저장소에 있습니다.

```bash

```

또는 GitHub 페이지에서 **"Code → Download ZIP"** 버튼을 눌러 다운로드한 후 압축을 풀어주세요.

- **GitHub 주소:** https://github.com/metacoding-ai-project/self-driving-car-v1

"메타코딩 씨, 잠깐 와봐요."

회의실 문을 열었더니, 테이블 위에 작은 로봇 청소기가 놓여 있었습니다. 바퀴가 달린 작은 플라스틱 덩어리. 왠지 그게 오늘부터 메타코딩의 운명을 바꿔놓을 것 같은 불길한 예감이 들었습니다.

"이거 보이죠? 우리 회사에서 자율주행 청소 로봇을 만들기로 했어요."

팀장님이 로봇 청소기를 톡톡 두드렸습니다.

"메타코딩 씨가 AI 파트를 담당해주세요."

순간 메타코딩의 머릿속이 하얘졌습니다.

'AI? 나를요?'

강화학습은 대학교 때 교수님이 PPT로 설명해주신 적이 있었습니다. 솔직히 절반도 이해를 못 했습니다. '벨만 방정식'이라는 글자가 화면에 떴을 때 바로 졸음이 밀려왔던 기억만 생생합니다. 그걸로 실제 제품을 만든다고요?

"걱정 마세요. 처음부터 실제 로봇에 넣을 필요 없어요. 일단 컴퓨터 시뮬레이터로 먼저 만들어봐요. 2주 안에 간단한 데모만 보여주시면 됩니다!"

팀장님은 밝게 웃으며 회의실을 나갔습니다. 메타코딩은 로봇 청소기와 둘이 남았습니다. 로봇 청소기의 동그란 버튼이 마치 눈처럼 보였습니다. '너도 나처럼 길을 모르는구나.'

### 😰 집에 돌아와서

그날 밤, 메타코딩은 노트북 앞에 앉아 인터넷을 뒤지기 시작했습니다.

"자율주행 강화학습 입문"

검색 결과에 **DQN**이라는 단어가 계속 나왔습니다. Deep Q-Network. 풀어보면 "깊은 Q 네트워크"인데, 이름만으로는 도무지 감이 잡히지 않았습니다.

그런데 읽다 보니 흥미로운 점이 있었습니다. 2013년에 DeepMind라는 회사가 이 DQN으로 아타리 게임을 사람보다 잘 하는 AI를 만들었다는 것입니다. 게임 AI랑 청소 로봇이 비슷하지 않을까? 둘 다 어떤 공간에서 목표를 향해 이동하는 거잖아.

> DQN = **강화학습** + **딥러닝**

"강화학습? 딥러닝? 그게 대체 뭐지?"

시계를 보니 밤 11시. 하지만 메타코딩의 눈은 오히려 더 반짝였습니다. 모르는 게 나오면 잠이 안 오는 체질이니까.

"좋아, 일단 큰 그림부터 보자."

### 🗺️ AI 세계의 전체 지도

메타코딩은 "AI 학습 종류"를 검색했습니다. 그리고 드디어 전체 그림이 보이기 시작했습니다.

AI가 배우는 방식은 딱 **3가지**입니다. 비유하면 이렇습니다.

**1. 지도학습 (Supervised Learning) — "선생님이 답을 알려주는 공부"**

시험 문제집에 정답지가 있다고 생각해보세요. 문제를 풀고, 정답을 확인하고, 틀린 걸 고칩니다. 이걸 수천 번 반복하면? 새로운 문제도 잘 풀게 됩니다.

쉽게 말하면, **"이건 고양이야" "이건 강아지야"** 하고 정답을 계속 알려주면, AI가 나중에 처음 보는 사진도 구별하게 되는 겁니다.

**2. 비지도학습 (Unsupervised Learning) — "정답 없이 스스로 분류하는 공부"**

이번엔 정답지가 없습니다. 대신 수백 장의 동물 사진을 AI한테 던져주면, AI가 스스로 "음, 이 그룹은 비슷하게 생겼고, 저 그룹은 또 다르네?" 하고 나눕니다. 정답을 안 알려줘도 패턴을 찾아내는 겁니다.

비유하면, 처음 가는 학교에서 아무 설명 없이 학생들을 관찰하다가 "아, 쟤네끼리 친한 그룹이구나" 하고 파악하는 것과 같습니다.

**3. 강화학습 (Reinforcement Learning) — "시행착오로 배우는 공부"**

정답지도 없고, 사진도 없습니다. 대신 **직접 해보고**, 잘하면 **보상**을 받고, 못하면 **벌**을 받습니다. 이걸 수만 번 반복하면서 점점 잘하게 됩니다.

비유하면? 자전거 배우는 것과 똑같습니다. 아무도 "페달을 13.7도 각도로 밟아"라고 안 가르쳐줍니다. 그냥 타보고, 넘어지고, 또 타보고, 균형 잡히면 "오 됐다!" 하고... 그러다 어느 날 자연스럽게 타게 되는 겁니다.

메타코딩은 노트에 정리했습니다.

```
┌─────────────────────────────────────────────────┐
│                   AI (인공지능)                    │
│                                                   │
│   ┌─────────┐  ┌──────────┐  ┌──────────┐       │
│   │ 지도학습  │  │ 비지도학습 │  │ 강화학습   │       │
│   └────┬────┘  └────┬─────┘  └────┬─────┘       │
│        │            │             │               │
│   ┌────┴────┐  ┌────┴────┐  ┌────┴─────┐        │
│   │ 분류    │  │ 군집화   │  │ Q러닝     │        │
│   │ 회귀    │  │ 차원축소  │  │ 정책경사  │        │
│   └─────────┘  └─────────┘  │ ...      │        │
│                              └──────────┘        │
│                                                   │
│   ──────────────────────────────────────────     │
│   딥러닝(신경망)은 별도의 종류가 아니라              │
│   위 3가지 모두에서 쓸 수 있는 🔧 도구!             │
│   ──────────────────────────────────────────     │
│                                                   │
│   ★ DQN = 강화학습(Q러닝) + 딥러닝(신경망)         │
│     → 이 책에서 다루는 것!                         │
└─────────────────────────────────────────────────┘
```

> **핵심 정리:** 딥러닝은 AI의 "종류"가 아닙니다! 딥러닝은 **도구**입니다. 망치가 집도 짓고 가구도 만드는 것처럼, 딥러닝(신경망)은 지도학습에도, 비지도학습에도, 강화학습에도 쓸 수 있습니다. 우리 책에서는 **강화학습 + 딥러닝 = DQN**을 배웁니다!

"아하!" 메타코딩이 무릎을 쳤습니다. "딥러닝이 따로 있는 게 아니라, 강화학습에 딥러닝을 갖다 붙인 게 DQN이구나!"

그런데 검색하다 보니 자꾸 **회귀**니 **분류**니 하는 단어가 나왔습니다. 이것도 알아야 할 것 같았습니다.

### 🎯 AI가 푸는 문제의 종류

메타코딩은 계속 읽었습니다. AI가 푸는 문제는 크게 보면 이렇게 나뉩니다.

**1. 회귀 (Regression) — "숫자를 맞혀라!"**

한 마디로, **숫자 하나를 예측**하는 겁니다.

- "내일 기온은 **몇 도**?"
- "이 집 가격은 **얼마**?"
- "이 학생의 다음 시험 점수는 **몇 점**?"

자율주행으로 치면? "목적지까지 남은 거리는 **몇 칸**?" 같은 문제입니다.

**2. 분류 (Classification) — "어느 쪽이야?"**

한 마디로, **카테고리를 고르는** 겁니다.

- "이 메일은 **스팸이야, 아니야**?"
- "이 사진은 **고양이야, 강아지야**?"

자율주행으로 치면? "이 칸은 **벽이야, 길이야**?" 같은 문제입니다.

**3. 강화학습 — "직접 해보고 배워라!"**

회귀나 분류와는 좀 다릅니다. 정답 데이터가 없습니다. 대신 **환경 안에서 직접 행동**하고, 그 결과로 **보상이나 벌**을 받으면서 배웁니다. 바로 **이 책 전체**가 강화학습입니다!

> **한 마디 정리:**
> - 회귀 = "**숫자** 맞히기" (얼마? 몇 도? 몇 점?)
> - 분류 = "**종류** 맞히기" (A야? B야?)
> - 강화학습 = "**직접 해보며** 배우기" (보상과 벌!)

"그런데..." 메타코딩은 고개를 갸우뚱했습니다. "회귀랑 분류는 대체 어떻게 작동하는 거지?"

### 📈 선형 회귀 — 직선 하나로 미래를 예측한다

회귀 중에서 가장 기본은 **선형 회귀**입니다. 쉽게 말하면 **"점들 사이에 직선 하나 긋기"**입니다.

메타코딩이 매일 걷는 걸음 수와 소모한 에너지를 기록했다고 생각해봅시다.

```
걸음 수 (x):   10    20    30    40    50
소모 에너지(y): 15    28    42    55    70

이걸 그래프에 점으로 찍으면, 거의 일직선!
→ 이 점들 사이에 가장 잘 맞는 직선을 긋는 게 선형 회귀!

직선 공식: y = 1.4x + 1

질문! 100걸음 걸으면 에너지가 얼마나 소모될까?
→ y = 1.4 × 100 + 1 = 141 에너지!
→ 아직 100걸음을 안 걸어봤는데 미래를 예측한 것!
```

> **한 마디로:** 선형 회귀 = **직선 하나로 미래의 숫자를 예측하는 것!** 중학교 때 배운 y = ax + b가 바로 이겁니다.

### 📊 로지스틱 회귀 — 확률로 분류한다

분류 중에서 가장 기본은 **로지스틱 회귀**입니다. 핵심은 간단합니다. **"확률을 계산해서, 높으면 O, 낮으면 X"**

자율주행으로 비유해봅시다. 벽까지 거리에 따른 충돌 확률은?

```
벽까지 거리:   1칸   2칸   3칸   5칸   10칸
충돌 확률:     95%   70%   40%   10%    2%

이 S자 모양의 곡선 = 시그모이드(Sigmoid) 함수!

시그모이드가 하는 일:
  어떤 숫자든 0과 1 사이의 확률로 바꿔준다!
  벽이 1칸 앞? → 0.95 (95%) → "부딪힌다!"로 분류
  벽이 10칸 앞? → 0.02 (2%) → "안 부딪힌다!"로 분류
```

> **한 마디로:** 로지스틱 회귀 = **시그모이드 함수로 확률을 구해서 O/X를 판단하는 것!** 이 시그모이드 함수, 기억해두세요. 1화에서 신경망을 배울 때 다시 등장합니다!

```python
def decide_action(self, environment):
    goal_x, goal_y = environment.goal_pos

    # 목적지까지의 거리 계산
    dx = goal_x - self.x   # 양수 = 오른쪽, 음수 = 왼쪽
    dy = goal_y - self.y   # 양수 = 아래쪽, 음수 = 위쪽

    # 우선순위 방향 결정
    preferred = []
    if dx > 0:   preferred.append(RIGHT)
    elif dx < 0: preferred.append(LEFT)
    if dy > 0:   preferred.append(DOWN)
    elif dy < 0: preferred.append(UP)

    # 우선순위대로 벽이 없는 방향으로 이동
    for direction in preferred:
        next_x, next_y = 다음_위치(direction)
        if not environment.is_wall(next_x, next_y):
            return direction   # 이 방향으로!
```

코드는 짧고 명쾌했습니다. "목적지가 어디 있나 보고, 그 방향으로 가되, 벽이면 다른 데로 가라." 사람이 보기에도 자연스러운 논리죠.

### 💥 왜 실패했을까?

이것이 **국소 최적화 함정(Local Optima)** 입니다. "지금 이 순간 가장 좋아 보이는 선택"만 반복하다 보면, 정작 전체적으로 봤을 때 최선의 길을 찾지 못하는 것이죠.

실생활에서도 이런 일은 흔합니다. 매일 같은 출근길만 고집하는 사람이 있습니다. 어느 날 공사 때문에 막혔는데, "원래 길이 제일 빠르니까"라며 1시간을 기다립니다. 돌아가면 20분이면 도착하는데 말이죠.

하지만 진짜 문제는 따로 있었습니다.

```
❌ if 문 (규칙 기반):
   "막히면 이쪽, 막히면 저쪽"
   → 1000번 실패해도 1001번째도 똑같이 실패!
   → 경험으로부터 배우지 않음!

✅ AI (강화학습):
   "이 상황에서 오른쪽으로 갔더니 벽이었어."
   "다음엔 위로 먼저 가봐야겠어."
   → 실패할수록 더 잘해짐! 점점 발전!
```

규칙 기반 시스템에는 **"기억"이 없습니다.** 어제의 실패를 오늘의 교훈으로 바꿀 수 없습니다. 하지만 AI는 다릅니다. AI는 실패를 기억하고, 그 기억에서 패턴을 찾아내고, 다음에는 더 나은 선택을 합니다.

## AI에게 세상을 보여주는 방법

본격적으로 AI를 만들기 전에, 메타코딩은 한 가지 중요한 질문과 마주했습니다.

### 🤔 "AI에게 뭘 알려줘야 하지?"

"전체 맵 정보를 다 줘야 할까?"

만약 전체 맵을 통째로 AI에게 보여준다면 어떻게 될까요? AI는 그 맵을 사진 찍듯 외워버립니다. "왼쪽에서 세 번째 칸에서 오른쪽으로 꺾어"라고 외우는 거죠. 당연히 맵이 바뀌면 아무것도 못 합니다.

마치 서울에서 부산까지 가는 길을 "신호등 237개째에서 좌회전"이라고 외우는 것과 같습니다. 도로 공사라도 하면 바로 길을 잃어버리죠.

"나침반처럼 방향만 알려주면 어떨까? '지금 목적지가 저쪽이야. 그리고 바로 주변에 벽이 있어.' 이 정도면 충분하지 않을까?"

이 아이디어가 핵심이었습니다.

### 📊 AI가 받는 정보: 상태 벡터 (State Vector)

**"상태 벡터"**란 현재 상황을 숫자들의 묶음으로 표현한 것입니다. AI는 글자나 그림이 아니라, **오직 숫자만** 이해합니다. 그래서 "지금 앞에 벽이 있어"를 "1"로, "앞에 벽이 없어"를 "0"으로 변환해서 알려줍니다.

우리 AI는 총 **11개의 숫자**를 받습니다:

```
AI가 보는 세상 (총 11개 숫자):

     [왼위벽] [위 벽] [오른위벽]
       ⓵=0    ⓶=1     ⓷=0        ← 벽이면 1, 빈칸이면 0

 [왼쪽벽]     🚗      [오른쪽벽]
   ⓸=0                  ⓹=0

  [왼아래벽] [아래벽] [오른아래벽]
    ⓺=1      ⓻=0      ⓼=0

 ⓽ 현재 방향: 오른쪽(→)
 ⓾ 목적지 X 방향: +0.6 (오른쪽으로 60% 거리)
 ⑪ 목적지 Y 방향: +0.4 (아래쪽으로 40% 거리)
```

왜 하필 11개일까요?

| 번호 | 정보               | 값 예시     | 역할                     |
| ---- | ------------------ | ----------- | ------------------------ |
| ①~⑧  | 주변 8칸 벽 유무   | 0 또는 1    | "지금 주변이 어떤가?"    |
| ⑨    | 현재 바라보는 방향 | 0~3 (0=위, 1=오른쪽, 2=아래, 3=왼쪽) | "나는 어디를 보고 있나?" |
| ⑩    | 목적지 X 방향 거리 | -1.0 ~ +1.0 | "목적지가 왼쪽? 오른쪽?" |
| ⑪    | 목적지 Y 방향 거리 | -1.0 ~ +1.0 | "목적지가 위? 아래?"     |

이 11개 숫자가 AI의 **"눈"** 입니다. 전체 지도가 아니라, "지금 내 주변"과 "목적지 방향"만 아는 것이죠.

> 💡 **쉽게 말하면:**
> AI는 **"바로 옆에 벽이 있나?"** + **"목적지가 어느 쪽이야?"** 이 두 가지만 알고 운전합니다.
> 마치 안대를 한 채로 손과 나침반만으로 길을 찾는 것과 비슷해요!

### 🔄 전처리(Preprocessing): AI의 통역사

방금 한 일을 AI 용어로 말하면 **전처리(Data Preprocessing)** 라고 합니다!

AI는 글자나 그림을 이해하지 못합니다. **오직 숫자만** 이해합니다. 그래서 세상의 모든 것을 숫자로 변환해줘야 합니다. 이 변환 작업이 바로 전처리입니다.

```
전처리(Preprocessing) = 세상을 AI가 이해할 수 있는 숫자로 변환!

전처리 전:   "앞에 벽이 있고, 목적지는 오른쪽 아래야"
전처리 후:   [0, 1, 0, 0, 0, 1, 0, 0, 1, +0.6, +0.4]

→ AI는 숫자만 이해하니까, 모든 것을 숫자로 바꿔주는 것이 전처리!
```

### 📏 정규화(Normalization): 숫자의 스케일 맞추기

전처리에서 한 가지 더 중요한 것이 있습니다. **숫자의 크기를 비슷하게 맞추는 것**입니다. 이것을 **정규화(Normalization)** 라고 합니다.

왜 필요할까요? 이렇게 생각해보세요. 시험을 두 과목 봤는데, **수학은 100점 만점**이고 **영어는 10점 만점**이에요.

```
정규화가 필요한 이유:

수학: 80점 (100점 만점)
영어: 9점 (10점 만점)

이 학생, 수학이 더 잘한 걸까요?
→ 수학은 80/100 = 80%
→ 영어는 9/10 = 90%
→ 사실 영어가 더 잘한 거예요!

하지만 숫자 크기만 보면?
→ "80 vs 9? 수학이 훨씬 잘했네!" ← 착각!
```

AI도 똑같은 착각을 합니다! 숫자가 큰 쪽이 더 중요하다고 오해해요.

```
❌ 정규화 안 한 경우:
  벽 유무: 0 또는 1       (작은 숫자)
  거리:    450             (큰 숫자!)
  → AI: "450이 1보다 크니까 거리만 신경 쓸래!"
  → 벽이 바로 앞에 있는데 무시! 💥 충돌!

✅ 정규화 한 경우:
  벽 유무: 0 또는 1       (0~1 범위)
  거리:    0.6             (0~1 범위로 변환!)
  → AI: "둘 다 비슷한 크기네, 둘 다 잘 살펴보자!"
  → 벽도 보고, 거리도 보고, 공정하게 판단! ✅
```

우리 시뮬레이터에서도 목적지 방향을 -1.0 ~ +1.0 범위로 변환했죠? 그게 바로 정규화입니다!

> 💡 **한 마디로:**
> - **전처리** = 세상을 숫자로 변환 (AI의 통역사)
> - **정규화** = 숫자의 크기를 비슷하게 맞추기 (만점을 통일!)

### 🎯 보상 시스템: AI에게 칭찬과 꾸중하기

정보만 준다고 AI가 배우는 건 아닙니다. **"잘했어!"(보상)** 와 **"안 돼!"(패널티)** 가 있어야 무엇이 좋고 나쁜지 알 수 있습니다.

강아지를 훈련시킬 때를 생각해보세요. "앉아!"를 했을 때 간식을 주면, 강아지는 "앉으면 좋은 일이 생기는구나!"를 배웁니다. 쓰레기통을 뒤지면 혼나니까, "쓰레기통은 건드리면 안 되는구나"를 배우죠.

AI도 마찬가지입니다:

```python
if 목적지 도달:
    reward = +100   # "완벽해! 바로 이거야!"
elif 목적지에 가까워짐:
    reward = +0.5   # "좋아, 방향은 맞아!"
elif 벽에 충돌:
    reward = -10    # "앗! 벽이야, 조심해!"
elif 시간 초과:
    reward = -50    # "너무 오래 걸렸어!"
```

이걸 **보상 함수(Reward Function)** 라고 합니다. AI의 선생님 같은 존재입니다.

여기서 중요한 점이 있습니다. 보상을 어떻게 설계하느냐에 따라 AI의 행동이 완전히 달라집니다. 예를 들어 "벽에 부딪히면 -10"이 아니라 "-1000"으로 했다면? AI는 벽이 너무 무서워서 아예 움직이지 않으려 할 수도 있습니다. 반대로 "-1"로 했다면? "벽에 좀 부딪혀도 괜찮지"라며 벽에 마구 부딪힐 수 있습니다.

**좋은 보상 함수를 설계하는 것은 AI에서 매우 중요한 기술입니다.** 마치 좋은 선생님이 적절한 칭찬과 꾸중의 균형을 잡는 것처럼요.

### 🧠 신경망(Neural Network): AI의 뇌

> **한 마디로:** 숫자를 넣으면, 계산을 거쳐서, 답이 나오는 기계!
> 입력(주변 상황 11개) → 계산(뉴런 64개) → 출력(직진/우회전/좌회전)

사람의 뇌에는 약 860억 개의 **뉴런(신경세포)** 이 있습니다. 이 뉴런들이 서로 신호를 주고받으면서 "생각"을 합니다. 신경망은 이걸 흉내 낸 거예요. 물론 860억 개는 무리고, 우리 AI는 소박하게 **78개의 뉴런**으로 시작합니다.

메타코딩은 이렇게 이해했습니다:

"자판기 같은 거구나! 동전(입력)을 넣으면 내부에서 뭔가 굴러가고, 음료(출력)가 나오는 거잖아. 신경망도 숫자를 넣으면 내부에서 계산하고, '직진해!' 같은 답이 나오는 거네!"

```
[우리 AI의 신경망 구조]

입력층 (11개)              은닉층 (64개 뉴런)         출력층 (3개)
┌─────────────────────┐                             ┌──────────────────┐
│ ① 왼위벽?   = 0     │──┐                      ┌─▶│ 직진   Q = 8.5   │
│ ② 위 벽?   = 1     │  │   ┌──────────────┐   │  │ 우회전 Q = 3.2   │
│ ③ 오른위벽? = 0     │──┤   │              │   │  │ 좌회전 Q = 2.1   │
│ ④ 왼쪽벽?  = 0     │  ├──▶│  64개 뉴런   │───┘  └──────────────────┘
│ ⑤ 오른쪽벽? = 0     │──┤   │  이 각각     │
│ ⑥ 왼아래벽? = 1     │  │   │  계산 중...  │           ↑
│ ⑦ 아래벽?  = 0     │──┤   │              │     Q값이 가장 높은
│ ⑧ 오른아래? = 0     │  │   └──────────────┘     행동을 선택!
│ ⑨ 현재방향  = 1(→)  │──┤
│ ⑩ 목적지dx = +0.6  │──┤        ↑
│ ⑪ 목적지dy = +0.4  │──┘   각 뉴런이 입력값에
└─────────────────────┘   가중치를 곱하고 더해서
                          최종 Q값을 만듦
```

11개 숫자를 넣으면, 자동으로 "직진/우회전/좌회전" 중 어느 것이 가장 좋은지 **Q값**으로 알려줍니다.

#### 🔬 뉴런 하나는 어떻게 계산할까?

은닉층의 뉴런 하나가 하는 일을 들여다봅시다. 생각보다 단순합니다.

```
[뉴런 하나의 계산 과정 — 3단계]

━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
1단계: 각 입력에 "가중치(weight)"를 곱한다

   입력값       가중치(w)      결과
   ───────    ×  ────────   =  ──────
   ① 0 (벽없음) × 0.3      =   0
   ② 1 (벽있음) × 0.8      =   0.8
   ③ 0          × 0.1      =   0
   ④ 0          × 0.5      =   0
   ⑤ 0          × 0.2      =   0
   ⑥ 1 (벽있음) × 0.7      =   0.7
   ⑦ 0          × 0.4      =   0
   ⑧ 0          × 0.1      =   0
   ⑨ 1 (오른쪽) × 0.6      =   0.6
   ⑩ 0.6        × 0.9      =   0.54
   ⑪ 0.4        × 0.3      =   0.12

━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
2단계: 전부 더하고, 편향(bias)도 더한다

   합계 = 0 + 0.8 + 0 + 0 + 0 + 0.7 + 0 + 0
        + 0.6 + 0.54 + 0.12 + 편향(0.1)
        = 2.86

━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
3단계: 활성화 함수를 통과시킨다 (ReLU)

   ReLU(2.86) = 2.86  ✅ (양수니까 그대로!)
```

이걸 수식으로 쓰면:

```
뉴런 출력 = ReLU( Σ(입력 × 가중치) + 편향 )
```

**가중치(weight)** 가 바로 AI가 학습하는 것입니다! 처음에는 가중치가 랜덤이라 엉터리 값이 나옵니다. 하지만 학습을 반복하면서 "이 가중치를 이렇게 바꾸면 더 정확해지겠다"를 발견하고, 조금씩 수정해나갑니다.

64개 뉴런이 각각 이런 계산을 하고, 그 결과들이 다시 합쳐져서 최종 Q값 3개가 만들어집니다.

> 💡 **어렵게 느껴지면 이것만 기억하세요!**
> - 뉴런은 **"입력 × 가중치를 더하는 계산기"**
> - 가중치는 **"이 정보가 얼마나 중요한지를 나타내는 숫자"**
> - 학습 = **"가중치를 조금씩 수정해서 더 정확한 답을 내도록 하는 것"**
> - 수식은 몰라도 됩니다! 이 세 줄만 기억하면 OK!

### 🧠 활성화 함수: ReLU와 Sigmoid

뉴런 계산의 마지막에 **활성화 함수**를 통과시킨다고 했죠. 이게 왜 필요할까요?

쉽게 말하면, 활성화 함수가 없으면 신경망이 아무리 복잡해도 결국 "단순한 계산기"밖에 안 됩니다. 복잡한 미로를 풀려면 **"복잡하게 생각할 수 있는 능력"**이 필요한데, 그게 바로 활성화 함수입니다!

```
[두 가지 대표적인 활성화 함수]

① ReLU (Rectified Linear Unit) — 우리 AI가 사용!
   ─────────────────────────────────────
   규칙: 음수면 0, 양수면 그대로 통과

   출력
    │        /
    │       /
    │      /
    │     /
    0─────────── 입력
     (음수는 0)

   예시: ReLU(2.86) = 2.86
         ReLU(-1.3) = 0
         ReLU(0)    = 0

   장점: 계산이 매우 빠름!
   현재 딥러닝에서 가장 많이 쓰이는 활성화 함수

② Sigmoid (시그모이드)
   ─────────────────────────────────────
   규칙: 어떤 값이든 0~1 사이로 부드럽게 압축

   출력
   1 ──────── ─────────────
    │        /
   0.5 ────/───────────── 입력
    │     /
   0 ───/

   예시: Sigmoid(10)  = 0.99 (거의 1)
         Sigmoid(0)   = 0.5  (딱 중간)
         Sigmoid(-10) = 0.01 (거의 0)

   장점: 확률을 표현하기 좋음!
   예: "목적지 도달 확률 73%" → 0.73

우리 v1~v5에서는 ReLU를 사용합니다.
은닉층에서 빠르게 계산하기 위해서죠.
Sigmoid는 주로 최종 출력에서 "확률"을 표현할 때 씁니다.
```

> **💡 비유로 이해하기:** ReLU는 "나쁜 신호 차단 필터"입니다. 뉴런이 "이 정보는 쓸모없어"라고 판단하면(음수) 완전히 차단(0)하고, "이건 유용해!"라고 판단하면(양수) 그대로 통과시킵니다.

> 💡 **어렵게 느껴지면 이것만 기억하세요!**
> - **ReLU** = 쓸모없는 정보는 차단! 유용한 정보만 통과! (우리 AI가 사용)
> - **Sigmoid** = 모든 숫자를 0~1 사이(확률)로 바꿔줌
> - 왜 필요한가? → 이게 있어야 AI가 **복잡한 문제**를 풀 수 있음!

### 🧠 Q값과 DQN: AI의 판단 기준

메타코딩: "그래서 AI가 뭘 기준으로 움직이는 거지? 직진할지 회전할지를 어떻게 결정해?"

답은 **Q값(Q-value)** 입니다. "이 상황에서 이 행동을 하면 **앞으로** 얼마나 좋을까?"를 나타내는 점수예요.

여기서 포인트는 **"앞으로"**라는 단어입니다. 지금 당장의 보상만이 아니라, **미래에 받을 보상까지 고려한 점수**입니다. 바로 이것이 0화의 if 규칙과 근본적으로 다른 점이에요. if 규칙은 "지금 이 순간"만 보지만, Q값은 "지금 이렇게 하면 나중에 어떻게 될까?"까지 생각합니다.

```
[예시: 현재 상황 — 목적지가 오른쪽 아래, 앞길이 열려 있음]

Q(현재 상황, 직진)   = 8.5  ← 가장 높음! → 이 행동 선택!
Q(현재 상황, 우회전) = 3.2
Q(현재 상황, 좌회전) = 2.1

AI는 Q값이 가장 높은 "직진"을 선택!
```

처음에는 이 Q값이 엉터리입니다. 가중치가 랜덤이니까요. 그러다 실패를 경험하면서 "이 상황에서 직진하면 벽이다 → Q값을 낮추자"를 배우고, 성공을 경험하면서 "이 상황에서 우회전하면 목적지에 가까워진다 → Q값을 올리자"를 배웁니다.

**이 과정을 수백, 수천 번 반복하면 Q값이 점점 정확해집니다. 이것이 DQN의 핵심입니다!**

> **DQN = Deep(깊은 신경망으로) + Q(Q값을) + Network(계산하는 네트워크)**

> 💡 **어렵게 느껴지면 이것만 기억하세요!**
> - **Q값** = 각 행동에 매기는 점수 (높을수록 좋은 행동)
> - **DQN** = Q값을 자동으로 계산해주는 AI의 뇌
> - 처음엔 랜덤으로 움직이다가, 점점 점수가 높은 행동만 골라함
> - 핵심: **실패하면서 점수를 수정하고, 그걸 반복하면 똑똑해진다!**

**문제 3: 너무 빨리 탐험을 멈춤**

```python
self.epsilon_decay = 0.995  # 빠르게 탐험 줄임
```

0.995가 왜 "빠르게" 줄이는 걸까요?

"잠깐, 0.995랑 0.998이랑 **겨우 0.003 차이**잖아! 그게 뭐가 달라?"

맞아요, 한 번만 보면 거의 같습니다. 하지만 비밀은 **"곱하기를 수백 번 반복한다"**는 것!

```
한 번만 곱하면?
  100 × 0.995 = 99.5
  100 × 0.998 = 99.8    ← 거의 차이 없음!

그런데 이걸 100번 반복하면?
  100 × 0.995 × 0.995 × 0.995 × ... (100번) = 60
  100 × 0.998 × 0.998 × 0.998 × ... (100번) = 82
```

> 비유: 매일 용돈의 0.5%를 쓰는 아이 vs 0.2%를 쓰는 아이
> 하루 차이는 티도 안 나지만, 1년 뒤에 한 명은 거의 빈털터리, 한 명은 절반 이상 남아있습니다!

나중에 v2에서 쓸 0.998과 비교해보면 확 느낌이 옵니다.

```
탐험 확률 변화 비교 (시작: 100%)

              0.995 (v1)          0.998 (v2)
100번 후 :    60% (반 넘게 줄었네!)   82% (아직 충분히 탐험!)
300번 후 :    22% (거의 안 탐험함)    55% (절반은 탐험!)
500번 후 :     8% (포기 수준...)     37% (아직 꽤 탐험!)
1000번 후:     1% (완전 멈춤!)       14% (가끔 탐험!)
```

같은 1000번 운전해도, 0.995는 **거의 안 탐험하는 로봇**이 되고, 0.998은 **가끔 새 길도 가보는 로봇**이 됩니다.

> 0.995는 "3일 만에 단골 식당만 가는 사람", 0.998은 "한 달은 이것저것 먹어보는 사람"

아직 세상을 충분히 탐험하지 않았는데 "이제 아는 걸로만 하자!"라며 탐험을 그만둔 것입니다.

이 세 가지 문제가 합쳐진 결과가 바로 **과적합(Overfitting)** 입니다.

```
[과적합을 한 마디로]

학생이 수학 시험을 준비했습니다.
문제집 1번 문제를 1000번 풀었습니다.
1번 문제는 눈 감고도 풀 수 있게 됐어요!

시험 날, 2번 문제가 나왔습니다.
→ 완전히 틀렸어요! ❌

이게 과적합입니다.
"연습 문제는 완벽한데, 새 문제는 전혀 못 푸는 것."
```

반대 개념은 **일반화(Generalization)** 입니다. "어떤 문제가 나와도 풀 수 있는 진짜 실력." 우리 AI가 가져야 할 능력이죠.

> 💡 **한 줄 요약:**
> - **과적합** = 문제를 외워서 푼 것 (가짜 실력)
> - **일반화** = 원리를 이해해서 푼 것 (진짜 실력)
> - AI 개발에서 가장 흔하고 위험한 함정이에요!

### 🧠 경사하강법(Gradient Descent): AI가 실수에서 배우는 원리

> **한 마디로:** AI가 "틀렸네? 다음엔 이쪽으로 수정하자!"를 반복하는 것!
> 산에서 가장 낮은 곳을 찾아 한 걸음씩 내려가는 것과 같습니다.

메타코딩: "AI가 스스로 배운다는 건 알겠는데, **정확히 어떻게** 배우는 거지?"

김선배: "간단해요. AI가 **틀릴 때마다, 틀린 방향의 반대로 조금씩 수정**하는 거예요."

이것이 바로 **경사하강법(Gradient Descent)** 입니다. 이름은 어렵지만, 원리는 놀라울 정도로 직관적이에요.

#### 🏔️ 비유: 안개 속 산에서 가장 낮은 곳 찾기

여러 봉우리와 골짜기가 있는 복잡한 산을 상상해보세요. 짙은 안개가 끼어서 주변이 하나도 안 보입니다. 전체 지도도 없습니다. 이 상황에서 **가장 낮은 곳(골짜기)**을 찾아야 합니다.

어떻게 하면 될까요?

```
전략: 발로 경사를 느끼면서 내려가기!

1. 발을 앞뒤좌우로 내밀어서 경사를 느낀다 → "기울기 계산"
2. 가장 가파르게 내려가는 방향으로 한 걸음  → "가중치 업데이트"
3. 다시 경사를 느끼고, 또 한 걸음          → "반복!"
4. 더 이상 내려갈 곳이 없으면 멈춘다       → "수렴"
```

이것이 경사하강법의 전부입니다! 생각보다 간단하죠?

여기서 **"경사를 느끼는 것"이 바로 미분(기울기 계산)** 입니다. 수학의 미분이 여기서 쓰입니다. AI가 "내가 지금 있는 위치에서 어느 방향으로 가면 오차가 줄어들까?"를 계산하는 것이 미분이에요.

#### 🏔️ 하지만 함정이 있습니다: 로컬 미니마!

산에는 여러 골짜기가 있습니다. 발로만 느끼면서 내려가다 보면 **"가짜 골짜기"**에 빠질 수 있습니다.

```
손실(Loss) — 높을수록 AI가 많이 틀린 것!

      ⛰️           ⛰️              ⛰️
     / | \         / | \            / | \
    /  |  \       /  |  \          /  |  \
   /   |   \     /   |   \        /   |   \
  /    |    \   /    |    \      /    |    \
 /     |     \_/     |     \    /     |     \
/      |      ↑      |      \__/     |      \____
       |   가짜      |               |        ↑
       |   골짜기!    |               |    진짜 최저점!
       |  (로컬      |               |    (여기를
       |   미니마)    |               |     찾아야 함!)
───────┴──────────────┴───────────────┴──────────▶ 가중치
```

> 🎨 **이 그림을 더 예쁘게 보고 싶다면?** 아래 프롬프트를 Gemini에게 보내보세요!
>
> *프롬프트: "경사하강법(Gradient Descent)을 설명하는 3D 산 풍경 일러스트를 그려줘. 여러 봉우리와 골짜기가 있는 산맥을 위에서 비스듬히 내려다보는 시점으로 그려줘. 왼쪽에 얕은 골짜기(로컬 미니마)가 있고, 오른쪽에 가장 깊은 골짜기(글로벌 미니마)가 있어. 산 위에 사람이 서 있고 안개가 자욱해서 앞이 안 보이는 상황. 발밑 화살표로 경사를 느끼며 내려가는 모습. '로컬 미니마(가짜 골짜기)'와 '글로벌 미니마(진짜 최저점)' 라벨을 한국어로 표시. 교육용 인포그래픽 스타일."*

"가짜 골짜기(로컬 미니마)"에 도달하면, 발로 느껴보는 모든 방향이 올라가는 것 같습니다. "여기가 가장 낮은 곳이구나!"라고 착각하죠. 하지만 실제로는 더 낮은 곳(진짜 최저점, 글로벌 미니마)이 멀리 있습니다.

#### 👣 보폭(Learning Rate)이 중요한 이유

안개 속에서 한 걸음의 크기를 **보폭(Learning Rate)** 이라고 합니다. 이 보폭이 학습의 운명을 결정합니다.

```
[보폭이 너무 클 때 — 최저점을 지나쳐버림!]

        ●←①시작!
       / \                       ●←③반대편 산!
```

```
   "이 근처가 가장 낮은 것 같은데, 정확히 어디지?"
```

#### 🔢 실제 AI에서 경사하강법은 이렇게 동작합니다

추상적인 산 이야기에서 구체적인 숫자로 내려와 봅시다.

```
[v2에서 한 번의 학습 과정 — 6단계]

━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
1단계: AI가 Q값을 예측한다

   현재 상황 → 신경망 통과 → Q(직진) = 7.0
   "직진하면 7.0점짜리 좋은 결과가 나올 거야!"

━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
2단계: 실제로 행동하고 결과를 확인한다

   직진했더니 → 목적지에 가까워짐!
   실제 보상 기반 올바른 Q값(정답): 10.0

━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
3단계: 오차(Loss)를 계산한다

   오차 = (예측 - 정답)²
        = (7.0 - 10.0)²
        = (-3.0)²
        = 9.0
   → "꽤 많이 틀렸네!"

   이 오차를 손실(Loss) 이라고 합니다.
   손실이 산의 높이입니다. 이걸 줄이는 게 목표!

━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
4단계: 기울기(Gradient)를 계산한다 — 이것이 미분!

   기울기 = 2 × (예측 - 정답)
          = 2 × (7.0 - 10.0)
          = -6.0

   기울기가 음수(-6.0) → "Q값을 올려야 해!"
   기울기가 양수였다면 → "Q값을 내려야 해!"

   이 기울기가 "경사"입니다.
   "어느 방향으로 가중치를 수정하면 오차가 줄어드는가?"
   를 알려주는 나침반 같은 존재!

━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
5단계: 가중치를 수정한다 (한 걸음 내딛기!)

   학습률(보폭) = 0.1
   수정량 = 학습률 × |기울기| = 0.1 × 6.0 = 0.6

   새 Q값 = 7.0 + 0.6 = 7.6
   → "10.0에 조금 가까워졌어!"

━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
6단계: 이걸 3000번 반복!

   7.0 → 7.6 → 8.1 → 8.5 → 9.0 → 9.5 → 9.8 → 10.0
   → 점점 정답에 가까워짐! ✅
```

> 💡 **어렵게 느껴지면 이것만 기억하세요!**
> 경사하강법을 한 문장으로 요약하면:
> **"AI가 예측하고 → 틀리면 → 틀린 만큼 수정하고 → 이걸 수천 번 반복하면 → 정답에 가까워진다!"**
> 숫자 계산은 컴퓨터가 알아서 합니다. 우리는 원리만 이해하면 돼요!

#### 🔄 역전파(Backpropagation): 오차를 거꾸로 추적하기

방금 "기울기를 계산한다"고 했는데, 신경망에는 뉴런이 64개나 있습니다. 각 뉴런의 가중치를 어떻게 수정할까요?

메타코딩: "뉴런이 64개나 되는데, 어떤 뉴런의 가중치를 얼마나 바꿔야 하는 거지?"

답은 **역전파(Backpropagation)** 입니다. 결과에서 발생한 오차를 **거꾸로** 추적하면서, 각 뉴런에게 "네가 이만큼 책임져!"라고 알려주는 방법이에요.

```
[역전파 흐름]

입력 → 은닉층 → 출력 → 오차 발생!
                              ↓
                         "Q값이 7인데 10이어야 했어!"
                              ↓
                    출력층 가중치 수정 ←
                              ↓
                    은닉층 가중치 수정 ←
                              ↓
                    입력층 가중치 수정 ←

마치 도미노를 거꾸로 세우는 것처럼,
오차의 "책임"을 뒤로 전파해서
각 가중치를 조금씩 수정합니다.
```

비유하면 이렇습니다. 축구에서 골을 넣지 못했을 때, 감독이 분석합니다. "슈팅이 빗나갔네(출력 오차). 왜? 패스가 정확하지 않았어(은닉층). 왜? 처음 볼 소유 때 위치 잡기가 나빴어(입력층)." 이렇게 원인을 거꾸로 추적하면서 각 선수(뉴런)에게 개선 방향을 알려주는 것이 역전파입니다.

#### 🔗 연쇄법칙(Chain Rule): 역전파의 비밀 무기

역전파가 "결과에서 거꾸로 돌아가면서 각 가중치를 조정한다"는 건 이해했죠? 그런데 한 가지 의문이 생길 겁니다.

**"거꾸로 돌아갈 때, 각 가중치를 얼마만큼 조정해야 하는 걸까?"**

이걸 정확하게 계산해주는 공식이 바로 **연쇄법칙(Chain Rule)** 입니다. 전화 게임(귓속말 릴레이)으로 이해해봅시다.

```
[상민이(a)] → [지유(b)] → [현우(c)] → [최종 발표(y)]
```

최종 발표에서 **"사과"**라고 해야 하는데 **"바과"**라고 틀렸어요! 누가 가장 책임이 클까요?

- **현우(c)**: 최종 발표 바로 앞이니까 가장 영향이 크다!
- **지유(b)**: 현우를 **거쳐서** 영향을 미치니까 좀 줄어든다.
- **상민이(a)**: 지유를 거치고, 현우를 또 거쳐야 하니까 **훨씬 줄어든다**.

이제 진짜 숫자를 넣어서 계산해봅시다!

```
a ──(×0.4)──▶ b ──(×0.3)──▶ c ──(×0.5)──▶ y(결과)

각 화살표의 숫자 = "다음 단계에 얼마나 영향을 미치는가"

결과 y가 틀렸다! 역전파 시작!

c의 영향력 = 0.5                 ██████████
b의 영향력 = 0.3 × 0.5 = 0.15   ███
a의 영향력 = 0.4 × 0.3 × 0.5 = 0.06  █

→ 멀수록 곱셈이 쌓여서 영향력이 줄어든다!
```

역전파는 이렇게 계산한 영향력으로 각 가중치를 조정합니다:

```
→ c의 영향력이 0.5니까, c의 가중치를 많이 고치자!
→ b의 영향력이 0.15니까, b의 가중치는 조금만 고치자.
→ a의 영향력이 0.06이니까, a의 가중치는 아주 살짝만 고치자.
```

왜 **"연쇄(Chain)"**법칙이냐고요? 앞 단계의 결과가 **사슬처럼 연결**되어서 다음 계산에 쓰이기 때문입니다. 마치 도미노가 넘어질 때 멀리 있는 도미노일수록 충격이 줄어드는 것과 같습니다!

> 💡 **어렵게 느껴지면 이것만 기억하세요!**
> - 연쇄법칙 = **"영향력 곱셈 릴레이"**
> - 결과에서 가까운 노드 → 영향력이 **크다** → 가중치를 **많이** 수정
> - 결과에서 먼 노드 → 곱셈이 쌓여서 영향력이 **작다** → 가중치를 **조금** 수정
> - 이것이 역전파가 **"각 가중치를 정확히 얼마나 고쳐야 하는지"** 아는 비결!

> 🎨 **역전파를 그림으로 이해하고 싶다면?** 아래 프롬프트를 Gemini에게 보내보세요!
>
> *프롬프트: "역전파(Backpropagation) 과정을 설명하는 다이어그램을 그려줘. 왼쪽에 입력층, 가운데에 은닉층, 오른쪽에 출력층이 있는 신경망 구조를 그리고, 오른쪽에서 왼쪽으로 빨간색 화살표가 흐르며 '오차를 거꾸로 전달'하는 모습을 표현해줘. 각 층에 '가중치 수정!' 라벨 표시. 축구 비유도 같이 그려줘: 출력층=슈팅 빗나감, 은닉층=패스 부정확, 입력층=위치 잡기 실패. 한국어 라벨, 교육용 인포그래픽 스타일."*

### 🔧 해결책 3: 천천히 탐험 줄이기 (Epsilon 조절)

**Epsilon(ε)** 은 "랜덤하게 새로운 것을 시도할 확률"입니다.

```
ε = 1.0 (100%): "모험가 모드! 완전 랜덤으로 움직여!"
ε = 0.5 (50%) : "절반은 모험, 절반은 아는 길로"
ε = 0.1 (10%) : "거의 아는 길, 가끔 새 시도"
ε = 0.0 (0%)  : "베테랑 모드! 배운 것만 활용!"
```

```python
# v1 (너무 빨리 탐험을 줄임)
self.epsilon_decay = 0.995  # 금방 0에 가까워짐

# v2 (천천히 탐험을 줄임)
self.epsilon_decay = 0.998  # 오래 탐험 유지
```

왜 이게 중요할까요?

```
v1의 문제:
Episode   1 : ε = 1.00 (100% 탐험)  "뭐든 해봐!"
Episode  50 : ε = 0.60 (60% 탐험)   "좀 알아가는 중"
Episode 100 : ε = 0.40 (40% 탐험)   "이제 아는 길로"
Episode 200 : ε = 0.10 (10% 탐험)   "거의 아는 길만"
→ 세상의 10%도 안 봤는데 탐험을 포기!
→ 한 가지 길만 알고 멈춤!

v2의 개선:
Episode  100 : ε = 0.90 (90% 탐험)  "아직 많이 탐험"
Episode  500 : ε = 0.60 (60% 탐험)  "여전히 탐험 중"
Episode 1000 : ε = 0.40 (40% 탐험)  "배워가는 중"
Episode 2000 : ε = 0.10 (10% 탐험)  "이제 활용 시작"
→ 충분히 탐험한 후에 활용! ✅
```

### 🧠 Exploration vs Exploitation: 탐험과 활용의 딜레마

> **한 마디로:** 처음엔 이것저것 시도하고(탐험), 나중엔 제일 좋은 걸 써먹는다(활용)!

여러분도 이런 경험 있지 않나요? "새로운 식당을 가볼까, 맨날 가는 단골 식당에 갈까?"

이것이 AI 분야에서도 가장 유명한 딜레마입니다.

```
탐험 (Exploration):
  "오늘은 저 골목 새 식당에 가볼까?"
  → 더 맛있는 곳을 발견할 수도!
  → 하지만 맛없는 곳일 수도 있음

활용 (Exploitation):
  "역시 우리 동네 단골집이 최고야!"
  → 안전한 선택, 확실한 만족
  → 하지만 더 좋은 곳을 영영 모름

딜레마:
  탐험만 하면 → 배운 것을 써먹지 못함
  활용만 하면 → 더 좋은 방법을 놓침

최적의 균형:
  처음엔 탐험을 많이, 나중엔 활용 위주
  (= Epsilon이 1.0에서 서서히 0.1로)
```

v1은 이 균형을 잘못 잡은 것입니다. 식당 세 군데만 가보고 "여기가 최고!"라며 다른 곳을 안 가본 셈이죠. v2에서는 충분히 다양한 식당을 돌아본 후에 단골집을 정합니다.

### 🔧 해결책 4 & 5: 추가 개선들

**새로운 길 발견 보상:**

```python
# 처음 가보는 곳이면 보너스!
if (next_x, next_y) not in self.visited_positions:
    reward += 0.2
```

같은 길만 빙빙 도는 것을 방지합니다. 새로운 칸을 밟을 때마다 "잘했어!"라는 작은 보상을 줘서 탐험을 격려하는 것이죠.

**학습 안정화 (Gradient Clipping):**

```python
# 한 번에 너무 크게 배우지 않도록 제한!
torch.nn.utils.clip_grad_norm_(self.policy_net.parameters(), 1.0)
```

```
Gradient Clipping 비유:

❌ 없을 때:
   어떤 날은 기울기가 100, 어떤 날은 0.001
   → 학습이 불안정, 폭주할 위험!

✅ 있을 때:
   기울기가 아무리 커도 1.0으로 제한
   → 매일 일정한 보폭으로 꾸준히 학습!

운전에 비유하면:
  급커브에서 갑자기 핸들을 확 꺾으면 위험하잖아요.
  "핸들은 최대 여기까지만!" 이라는 제한을 두는 것.
```

### 🧠 경험 리플레이(Experience Replay): AI의 복습 노트

> **한 마디로:** AI가 겪은 일을 "오답 노트"에 적어두고, 나중에 랜덤으로 꺼내 복습하는 것!

v2에서 한 가지 더 중요한 기법이 있습니다. **경험 리플레이**입니다.

AI는 움직일 때마다 경험을 저장합니다:

```
경험 = (현재 상태, 행동, 보상, 다음 상태)

예시:
("벽이 오른쪽에 있고 목적지가 아래", "직진", +0.5, "벽이 없고 목적지가 아래")
```

이 경험들을 **경험 창고(Replay Buffer)** 에 쌓아둡니다. 그리고 학습할 때 이 창고에서 랜덤으로 꺼내서 복습합니다.

```
[경험 리플레이 비유]

학생의 오답 노트 같은 것!

1. 문제를 풀 때마다 오답 노트에 기록
   "3번 문제 틀림. 정답은 이거."

2. 복습 시간에 오답 노트에서 랜덤으로 꺼내서 풀기
   → 오래 전에 틀린 문제도 다시 복습!

3. 왜 랜덤으로? 순서대로 복습하면
   "앞부분은 잘 기억나는데 뒷부분은 까먹음"
   → 골고루 복습해야 전체 실력이 향상!
```

```
경험 창고 (Replay Buffer):
┌────────────────────────────────────────────┐
│ 경험 1: 직진 → 벽 충돌 (-10)              │
│ 경험 2: 우회전 → 목적지 접근 (+0.5)       │
│ 경험 3: 직진 → 목적지 도달! (+100)        │
│ ...                                        │
│ 경험 10000: 좌회전 → 빈 공간 (0)          │
└────────────────────────────────────────────┘

학습할 때: 여기서 32개를 랜덤으로 뽑아서 복습!
(이 32개를 "미니배치(Mini-batch)"라고 합니다)
```

> **💡 미니배치(Mini-batch):** 경험 창고에서 한 번에 32개씩 뽑아서 학습하는 것을 **미니배치 학습**이라고 합니다. 왜 하나씩 안 하고 32개씩? 하나씩 하면 학습이 불안정하고(한 경험에 너무 좌우됨), 전부 다 하면 너무 느립니다. 32개는 "적당히 안정적이면서 적당히 빠른" 절충안입니다.

### 📝 학습 단위 용어 정리

여기서 잠깐, AI 세계에서 자주 쓰는 학습 단위를 정리해봅시다. 비슷한 단어가 여러 개라 헷갈릴 수 있거든요!

```
학습 단위 정리:

에피소드(Episode): 시작 → 목적지 도달(또는 실패)까지 한 판
  → 우리 자율주행에서 사용!
  → "에피소드 500번 학습" = 500판 플레이!

에포크(Epoch): 전체 데이터를 한 바퀴 돌린 것
  → 이미지 분류 같은 지도학습에서 사용!
  → "10 에포크 학습" = 전체 데이터를 10번 반복!

이터레이션(Iteration): 미니배치 하나를 학습한 한 번
  → 우리 AI에서 경험 32개 뽑아서 학습하는 한 번!
  → 1 에피소드 안에 여러 번의 이터레이션이 있음

쉽게 비유하면:
  에피소드 = 시험 1회
  에포크   = 문제집 1회독
  이터레이션 = 문제 1번 풀기
```

> 💡 **우리 책에서는 주로 "에피소드"를 씁니다.** 강화학습은 "에피소드" 단위로 학습하고, 지도학습은 "에포크" 단위로 학습한다는 것만 기억하면 됩니다!

### 📚 훈련셋 vs 테스트셋 — AI에서 가장 중요한 원칙

메타코딩은 이 개념을 노트에 크게 적었습니다.

```
[학교 시험에 비유]

연습 문제집 (훈련셋):       시험지 (테스트셋):
┌────────────────┐         ┌────────────────┐
│ 1번: 2 + 3 = ? │         │ 21번: 7 + 8 = ?│
│ 2번: 5 × 4 = ? │  ──AI──▶│ 22번: 3 × 9 = ?│
│ ...            │   학습  │ ...            │
│ 20번: 8 - 2 = ?│         │ 30번: 6 ÷ 2 = ?│
└────────────────┘         └────────────────┘
  이걸로 공부               처음 보는 문제!
                            이걸로 진짜 실력 평가!
```

이 원칙은 AI 분야 전체에서 통용됩니다. ChatGPT도, 이미지 인식 AI도, 넷플릭스 추천 AI도, 모두 **훈련셋과 테스트셋을 분리**합니다.

> 💡 **어렵게 느껴지면 이것만 기억하세요!**
> - **훈련셋** = 공부할 때 쓰는 문제집 (이걸로 배움)
> - **테스트셋** = 시험지 (처음 보는 문제! 이걸로 진짜 실력 평가)
> - 핵심: **공부에 쓴 문제로 시험 보면 안 된다!** (그건 외운 것일 뿐)

### 🔧 v3의 수정

수정 자체는 놀랍도록 간단했습니다. 20개 맵을 섞어서 **16개는 학습용, 4개는 시험용**으로 나눴습니다.

```python
# v3의 핵심 변경: 맵을 훈련용과 시험용으로 나눈다!

# 20개 맵을 섞어서 16개는 훈련용, 4개는 시험용으로 나누기
all_map_ids = list(range(20))         # [0, 1, 2, ..., 19]
random.shuffle(all_map_ids)            # 랜덤으로 섞기!
train_map_ids = all_map_ids[:16]       # 16개로 학습
test_map_ids = all_map_ids[16:]        # 4개로 시험 (처음 보는 맵!)

# 훈련할 때는 train_map_ids에 있는 맵만 사용!
# 테스트할 때는 test_map_ids에 있는 맵으로 진짜 실력 확인!
```

코드 몇 줄의 변경이지만, 그 의미는 거대했습니다. "거울 앞에서 연습하던 것"을 "진짜 무대에 세우는 것"으로 바꾼 것이니까요.

### 📊 "성공률"의 진짜 이름: 정확도(Accuracy)

그런데 김선배가 한 가지 더 알려줬습니다.

"메타코딩 씨, 지금 쓰는 '성공률'이라는 말 있잖아요. AI 세계에서는 이걸 **정확도(Accuracy)**라고 불러요."

```
우리가 쓰는 "성공률" = AI 용어로 "정확도(Accuracy)"!

자율주행 예:
  정확도 68% = 100번 중 68번 성공 = 우리가 쓰는 성공률!

이미지 분류 예:
  정확도 95% = 고양이 사진 100장 중 95장을 맞힘!

→ 같은 개념, 다른 이름일 뿐!
```

AI 세계에서는 정확도 외에도 다양한 평가 지표가 있지만, 우리 자율주행에서는 **정확도(성공률)**만으로 충분합니다!

### 🔄 더 정확하게 측정하는 방법: 교차검증

김선배가 커피를 한 모금 마시더니 덧붙였습니다.

"그런데 시험지가 하나만 있으면 어떨까요? 운 좋게 쉬운 문제만 나올 수도 있잖아요."

```
시험지 1개로만 평가하면:
  → 운 좋으면 높은 점수, 운 나쁘면 낮은 점수
  → 진짜 실력인지 운인지 구분 못함!

시험지를 5개 만들어서 돌아가며 보면:
  → 5번의 평균 = 진짜 실력!
```

이걸 **교차검증(Cross-Validation)**이라고 합니다.

```
교차검증 — 자율주행 버전:

20개 맵을 5묶음(4개씩)으로 나눈다:
  묶음 A: 맵 [0, 1, 2, 3]
  묶음 B: 맵 [4, 5, 6, 7]
  묶음 C: 맵 [8, 9, 10, 11]
  묶음 D: 맵 [12, 13, 14, 15]
  묶음 E: 맵 [16, 17, 18, 19]

1차: A로 시험, B+C+D+E로 학습 → 70%
2차: B로 시험, A+C+D+E로 학습 → 65%
3차: C로 시험, A+B+D+E로 학습 → 72%
4차: D로 시험, A+B+C+E로 학습 → 68%
5차: E로 시험, A+B+C+D로 학습 → 66%

평균: (70+65+72+68+66) / 5 = 68.2% ← 이게 진짜 실력!
```

우리 v3에서는 간단하게 훈련셋/테스트셋만 나눴지만, 실무에서는 교차검증으로 더 정확하게 측정합니다. 하지만 학습을 5번 해야 하니 시간이 5배 걸린다는 단점이 있어요!

> 💡 **어렵게 느껴지면 이것만 기억하세요!**
> - 교차검증 = **시험지를 여러 개 만들어서 돌아가며 시험보고 평균을 내는 것!**
> - 왜? = 한 번의 시험 결과보다 여러 번의 평균이 더 신뢰할 수 있으니까!

### 🧠 Learning Rate Scheduling: 보폭 자동 조절

> **"처음엔 성큼성큼, 나중엔 살금살금!"**

```
[비유: 새 교과서를 공부하는 방법]

1단계: 빠르게 훑어보기 (큰 Learning Rate = 0.001)
   "우선 목차랑 소제목만 쭉 읽어보자!"
   → 전체 구조 파악!
   → "아, 이 책은 대충 이런 내용이구나!"

2단계: 본문 차근차근 읽기 (중간 Learning Rate = 0.0005)
   "이제 각 챕터를 하나씩 읽어보자"
   → 핵심 개념 이해!

3단계: 중요 부분 정독 (작은 Learning Rate = 0.0001)
   "이 부분은 핵심이니까 세 번 읽자!"
   → 디테일까지 완벽히!

→ 처음부터 한 글자씩 정독하는 것보다 훨씬 효율적!
```

경사하강법의 산 비유로 돌아가면:

```
[학습률이 변하는 과정 — 산에서 최저점 찾기]

1단계: 큰 보폭 (LR = 0.001)
        ●←시작
       / \                ⛰️
      / ↘↘\              / \
     /  ↘↘ \            /   \
    /    ↘↘  \          /     \
   /       ↘↘ \___    /       \____
  /          ●       \/
           "이 근처가 가장 낮은 것 같아!"
  ─────────────────────────────────────▶ 가중치

2단계: 작은 보폭 (LR = 0.0001)
                 ●←여기서부터 조심조심
                ↓↓↓
               ↓↓↓↓↓
              ×  "여기가 진짜 최저점!" ✅
  ─────────────────────────────────────▶ 가중치
```

### 🔧 v4 코드 소개

```python
class DQNAgent:
    def __init__(self):
        self.initial_lr = 0.001   # 처음: 큰 보폭으로 빠르게
        self.min_lr = 0.0001      # 마지막: 작은 보폭으로 세밀하게

    def update_learning_rate(self, episode):
        # 에피소드가 진행될수록 학습률이 줄어듦
        decay_rate = 0.998
        self.current_lr = self.initial_lr * (decay_rate ** episode)
        self.current_lr = max(self.current_lr, self.min_lr)

        # 옵티마이저에 적용
        for param_group in self.optimizer.param_groups:
            param_group['lr'] = self.current_lr
```

`decay_rate = 0.998`은 매 에피소드마다 학습률을 0.2%씩 줄인다는 뜻입니다. 아주 조금씩, 천천히 보폭을 줄여나가는 것이죠.

### 🏂 우리 AI가 쓰는 옵티마이저: Adam!

LR Scheduling 코드를 보다가 메타코딩이 또 다른 것을 발견했습니다.

"선배님, 코드에 `Adam`이라는 게 있는데 이건 뭐예요?"

김선배가 웃으며 설명했습니다.

"경사하강법을 기억하죠? 오차를 줄이는 방향으로 가중치를 수정하는 거. 그 경사하강법에도 종류가 있어요."

```
옵티마이저(Optimizer) = 경사하강법의 업그레이드 버전들!

SGD (기본 경사하강법):
  모든 가중치를 같은 보폭으로 수정
  비유: 직진만 하는 초보 스키어
  → 단순하지만, 울퉁불퉁한 지형에서 비효율적

Adam (우리가 쓰는 것!):
  각 가중치마다 보폭을 자동으로 조절!
  비유: 지형에 맞춰 자세를 바꾸는 프로 스키어
  → 가파른 곳은 조심, 완만한 곳은 빠르게!
```

```
산에서 최저점을 찾는 비유:

SGD:  ●→→→→→→→→→→→→→→→→→→●
      (같은 보폭으로 쭉 직진!)
      → 때로 지그재그로 방향이 흔들림

Adam: ●→→→→→ →→ → → ●
      (처음엔 크게, 나중엔 상황에 맞춰!)
      → 더 빠르고 안정적으로 도착!
```

"Adam은 'Adaptive Moment Estimation'의 줄임말인데, 이름은 몰라도 돼요. 중요한 건 **SGD보다 똑똑하게 가중치를 수정한다**는 것!"

우리 AI 코드에서는 이미 Adam을 사용하고 있습니다.

```python
# agent.py에서 (v1부터 쭉 사용 중!)
self.optimizer = optim.Adam(self.model.parameters(), lr=0.001)
#                   ^^^^
#                   SGD 대신 Adam을 쓰고 있었던 것!
```

> 💡 **어렵게 느껴지면 이것만 기억하세요!**
> - **옵티마이저** = 경사하강법의 종류 (가중치를 어떻게 수정할지 결정)
> - **SGD** = 기본형. 같은 보폭으로 직진 (초보 스키어)
> - **Adam** = 업그레이드형. 상황에 맞춰 보폭 자동 조절 (프로 스키어)
> - 실무에서는 대부분 **Adam**을 씁니다!

```
    지도학습 | 비지도학습 | 강화학습 ★ | 딥러닝 ★
```

### 💭 학습과 추론은 다르다

메타코딩은 다시 김선배를 찾아갔습니다.

"선배님, 팀장님이 추론 속도를 최적화하라고 하시는데... 추론이 뭔가요?"

김선배가 웃으며 화이트보드에 적었습니다.

```
AI의 두 단계:

학습 (Training):
  → AI가 "배우는" 과정
  → 공장에서 한 번 (몇 시간~며칠)
  → 끝나면 모델 파일(.pth)로 저장
  → 느려도 괜찮음!

추론 (Inference):
  → 배운 걸 "실제로 사용하는" 과정
  → 매번 청소할 때마다!
  → 빠를수록 좋음! (배터리 절약, 반응 빠름)
```

```
사람으로 비유하면:

학습 = 운전면허 학원 다니기 (한 번)
  → 몇 주 걸려도 괜찮음
  → 열심히 배우면 됨

추론 = 매일 아침 출근 운전 (매일)
  → 빠르고 자연스러워야 함
  → 매번 교과서 펴보면서 운전할 수 없잖아요!
```

"학습은 한 번이면 되지만, 추론은 청소할 때마다 해야 하잖아요. 매번 신경망 45ms를 기다리는 건 비효율적이에요."

### 💡 메타코딩의 아이디어: 캐싱!

"그러고 보니... 같은 집에서 매일 청소하면 비슷한 경로로 다니는데, 매번 신경망 계산을 하는 게 낭비 아닌가? 이미 성공한 경로를 저장해두면 더 빠르지 않을까?"

```
네비게이션에 비유하면:

❌ 매번 새로 계산:
  "서울→부산 경로를 다시 계산합니다... 45ms"
  (매일 같은 길인데 매번 계산?)

✅ 자주 가는 길은 저장:
  "저장된 경로입니다! 바로 안내합니다. 12ms"
  (3.75배 빠름!)
```

### 🔧 캐싱 시스템 코드 소개

```python
class ActionCache:
    """성공한 경험을 저장하는 캐시"""
    def __init__(self):
        self.cache = {}  # 상태 → 행동 매핑

    def get(self, state):
        """이 상황을 본 적 있나?"""
        state_key = tuple(round(x, 2) for x in state)
        return self.cache.get(state_key, {}).get('action', None)

    def store(self, state, action, success):
        """성공한 행동만 저장!"""
        if success:
            state_key = tuple(round(x, 2) for x in state)
            self.cache[state_key] = {'action': action}
```

핵심은 **성공한 경험만 저장**한다는 것입니다. 실패한 경험까지 저장하면 "여기서 벽에 부딪혔었지"라는 나쁜 기억을 따라갈 수도 있으니까요.

### 💡 두 가지 전략: 정적 vs 동적 환경

김선배가 중요한 포인트를 짚어줬습니다.

"캐시를 쓸 때는 환경에 따라 전략을 달리해야 해요."

**전략 1: 정적 환경 (공장, 창고 — 장애물이 고정)**

```
캐시에 있으면 → 캐시 사용! (12ms, 3.75배 빠름!)
캐시에 없으면 → 신경망 계산 (45ms)

매일 같은 구조인 창고에서는 캐시가 매우 효과적!
```

**전략 2: 동적 환경 (가정집 — 가구 이동, 사람 이동)**

```
항상 신경망(Policy)이 먼저! (45ms, 하지만 안전!)
캐시는 참고만 → 캐시와 다르면 신경망 우선!

사람이 돌아다니는 집에서는 안전이 최우선!
```

```
운전자(Policy)가 네비(Cache)보다 우선인 이유:

네비: "이 길로 직진하세요"
운전자: "어? 앞에 공사중이야! 우회해야겠어!"

→ 실시간 판단(Policy)이 저장된 기억(Cache)보다 중요!
→ 눈앞의 현실이 과거의 기억보다 정확!
```

> 💡 **어렵게 느껴지면 이것만 기억하세요!**
> - **캐시** = 자주 가는 길을 저장해서 빠르게 이동 (네비 즐겨찾기)
> - **Policy** = AI가 실시간으로 판단하는 것 (운전자의 눈)
> - 핵심: **저장된 길보다 눈앞의 현실이 더 중요하다!**
> - 같은 집이면 캐시로 빠르게, 상황이 바뀌면 AI가 직접 판단!

```
[자율주행 의사결정 트리]

              "앞에 벽이 있나?"
                /          \
              Yes           No
               |             |
     "목적지가 오른쪽?"    "목적지 방향으로"
         /        \          → 직진!
       Yes        No
        |          |
   "우회전!"    "좌회전!"
```

DQN은 숫자 수천 개를 곱하고 더하는 복잡한 계산으로 판단하지만, 의사결정 트리는 **질문과 대답만으로** 판단합니다. 마치 스무고개 게임처럼요!

> 🎨 **이 그림을 더 예쁘게 보고 싶다면?** 아래 프롬프트를 Gemini에게 보내보세요!
>
> *프롬프트: "자율주행 자동차의 의사결정 트리(Decision Tree) 다이어그램을 그려줘. 맨 위 루트 노드에 '앞에 벽이 있나?'가 있고, Yes로 가면 '목적지가 오른쪽인가?', No로 가면 '직진!'으로 연결돼. '목적지가 오른쪽인가?'에서 Yes는 '우회전!', No는 '좌회전!'으로 이어져. 나무(tree) 모양으로, 각 노드를 둥근 사각형으로, 최종 결정(잎)은 초록색으로 강조해줘. 깔끔한 인포그래픽 스타일, 한국어 라벨 포함."*

#### 트리가 자율주행을 배우는 과정

방금 실행한 `train_tree.py`에서 트리는 수집된 데이터를 보면서 **스스로 질문을 만들어** 갑니다.

```python
# train_tree.py 핵심 부분

# 의사결정 트리 학습!
tree = DecisionTreeClassifier(max_depth=10, random_state=42)
tree.fit(X_train, y_train)    # 데이터를 보면서 질문을 만든다!
```

`max_depth=10`은 "질문을 10번까지만 해라"라는 뜻입니다. 질문을 너무 많이 하면 과적합에 빠지거든요. v3에서 배운 것처럼요!

#### 결과 다시 보기: 트리가 중요하게 보는 정보

아까 결과에 "트리가 가장 중요하게 보는 정보"가 나왔죠? 이것이 바로 **Feature Importance(특성 중요도)** 입니다.

```
트리가 가장 중요하게 보는 정보:

  1. 목적지Y 방향 : 0.312  ★★★★★
  2. 목적지X 방향 : 0.278  ★★★★
  3. 위 벽         : 0.145  ★★★
  4. 아래 벽       : 0.089  ★★
  5. 현재 방향     : 0.076  ★

→ "목적지가 어디인지"가 가장 중요하고,
   "바로 앞에 벽이 있는지"가 그 다음으로 중요하다!
```

이게 바로 의사결정 트리의 최대 장점입니다. **"왜 그렇게 판단했는지 사람이 이해할 수 있다!"** 이걸 AI에서는 **"해석 가능성(Interpretability)"**이라고 부릅니다.

DQN은 어떤가요? 신경망 안에 숫자가 수천 개 들어있는데, 왜 직진을 선택했는지 사람이 들여다봐도 도무지 이해할 수 없습니다. 그냥 "컴퓨터가 계산했대"가 전부예요.

```
DQN (블랙박스):
  입력 → [????복잡한 계산????] → "직진!"
  사람: "왜 직진이야?"
  DQN: "......(수천 개 숫자를 보여줌)"
  사람: "무슨 소리야?"

의사결정 트리 (해석 가능!):
  "앞에 벽? No → 목적지가 오른쪽? No → 직진!"
  사람: "아, 앞에 벽이 없고 목적지가 앞쪽이니까 직진이구나!"
  사람: "이해가 돼!"
```

> 💡 **어렵게 느껴지면 이것만 기억하세요!**
> - 의사결정 트리 = **"스무고개 게임"** 하듯이 질문을 던져서 답을 찾는 AI
> - 최대 장점 = **왜 그렇게 판단했는지 사람이 이해할 수 있음!** (해석 가능성)
> - 최대 단점 = 복잡한 상황에서 **DQN보다 성능이 낮음**

### 3단계: 랜덤 포레스트 학습 (train_forest.py)

> **한 줄 요약:** 트리 1개는 틀릴 수 있지만, 100개가 투표하면 정확해진다!

#### 실행해보기!

```bash
python train_forest.py
```

#### 결과 확인

```
==================================================
랜덤 포레스트로 자율주행 배우기!
==================================================
트리 100개 학습 중...

앙상블 효과 비교:
  트리 1개 정확도:          약 85%
  트리 100개(포레스트) 정확도: 약 89%
  → 포레스트가 약 4% 더 정확! (투표의 힘!)
==================================================
```

오! 2단계에서 트리 1개로 85%였는데, 100개를 합치니 89%로 올랐습니다! 도대체 어떻게?

#### 랜덤 포레스트란?

혼자 판단하면 틀릴 수 있지만, **100명이 투표하면** 정답에 가까워집니다. 이걸 AI에서는 **앙상블(Ensemble)**이라고 부릅니다.

```
[앙상블의 원리 — 투표!]

트리 1호:  "직진!"
트리 2호:  "직진!"
트리 3호:  "우회전!"
트리 4호:  "직진!"
트리 5호:  "직진!"
   ...
트리 99호: "직진!"
트리 100호: "직진!"

투표 결과: 직진 80표 / 우회전 15표 / 좌회전 5표
       → "직진!"
```

학교에서 반장 선거를 하는 것과 비슷합니다. 한 명의 의견보다 30명의 투표가 더 공정하고 정확하죠?

#### 왜 "랜덤"인가?

중요한 점이 있습니다. 트리 100개를 **똑같이** 만들면 의미가 없어요. 같은 사람 100명에게 물어보는 것과 같으니까요. 그래서 랜덤 포레스트는 각 트리를 만들 때 **다른 데이터, 다른 질문**을 사용합니다.

```
왜 "랜덤" 포레스트인가?

트리 1호: 데이터 70%를 랜덤으로 뽑아서 학습
          + 질문할 때 사용할 정보도 랜덤으로 선택
트리 2호: 다른 70%를 뽑아서 학습
          + 다른 정보를 랜덤으로 선택
트리 3호: 또 다른 70%를...
   ...
트리 100호: 또 다른 조합으로!

→ 100개 트리가 각자 다른 관점에서 판단!
→ 투표하면 편향된 판단이 상쇄됨!
```

비유하면 이렇습니다. 시험 범위가 100페이지인데, 학생 A는 1~70페이지를 공부하고, 학생 B는 20~90페이지를 공부하고, 학생 C는 30~100페이지를 공부했어요. 혼자서는 모르는 범위가 있지만, 셋이 모여서 답을 맞춰보면 거의 모든 범위를 커버할 수 있죠!

#### 코드로 보면

```python
# train_forest.py 핵심 부분

# 랜덤 포레스트 학습! (트리 100개!)
forest = RandomForestClassifier(
    n_estimators=100,    # 트리 100개!
    max_depth=10,        # 각 트리는 질문 10번까지
    random_state=42
)
forest.fit(X_train, y_train)
```

`n_estimators=100`이 "트리 100개를 만들어라"라는 뜻입니다. 이 한 줄이 앙상블의 핵심이에요!

> 💡 **어렵게 느껴지면 이것만 기억하세요!**
> - 랜덤 포레스트 = **트리 100개가 투표해서 결정!**
> - 왜 더 좋은가? = 한 명이 틀려도 다수가 보정해줌
> - 핵심: **다양한 관점의 조합 > 한 명의 천재**

> *프롬프트: "랜덤 포레스트(Random Forest) 앙상블 투표 다이어그램을 그려줘. 왼쪽에 트리 1~100까지 여러 개의 작은 의사결정 트리가 나란히 있고, 각 트리에서 나온 결과(직진/우회전/좌회전)가 가운데 '투표함'으로 모인 다음, 오른쪽에 최종 결정 '직진!'이 나오는 구조. 트리는 3~4개만 대표로 그리고 나머지는 ...으로 생략. 깔끔한 인포그래픽 스타일, 한국어 라벨 포함."*

### LSTM/RNN 개념 소개: 기억하는 AI

> **이 섹션은 개념만 소개합니다. 실제 코드는 없습니다!**

메타코딩이 시뮬레이터를 보다가 말했습니다.

"김선배님, 자동차가 같은 곳을 왔다 갔다 할 때가 있어요. '아까 거기 갔는데 막다른 길이었잖아'를 기억하면 안 가겠죠?"

김선배가 고개를 끄덕였습니다.

"맞아요. 지금 AI는 **현재 이 순간만** 보고 판단해요. 1초 전에 어디 있었는지 기억을 못 하죠. 근데 **과거를 기억하는 신경망**이 있어요."

#### 일반 신경망 vs RNN vs LSTM

```
일반 신경망 (우리 DQN):
  "지금" 만 봄
  ┌──────┐     ┌──────┐     ┌──────┐
  │ t=1  │     │ t=2  │     │ t=3  │
  │상태→판단│   │상태→판단│   │상태→판단│
  └──────┘     └──────┘     └──────┘
      ↑            ↑            ↑
  각각 독립!    이전을 모름!   이전을 모름!

RNN (순환 신경망):
  "과거도 기억"함
  ┌──────┐     ┌──────┐     ┌──────┐
  │ t=1  │────▶│ t=2  │────▶│ t=3  │
  │상태→판단│   │상태+기억│   │상태+기억│
  └──────┘  기억 └──────┘ 기억 └──────┘
              전달!          전달!

  t=3에서 판단할 때:
  "t=1에서 왼쪽으로 갔고, t=2에서 벽이었어.
   그러니까 t=3에서는 오른쪽으로 가야 해!"
```

하지만 RNN에는 약점이 있습니다. 기억이 **점점 흐려진다**는 것이에요. 마치 전화기 게임처럼, 사람을 거칠수록 원래 메시지가 왜곡되는 것과 같습니다. 10걸음 전의 기억은 거의 사라져요.

그래서 나온 것이 **LSTM(Long Short-Term Memory, 장단기 기억)** 입니다.

```
LSTM의 핵심: "무엇을 기억하고, 무엇을 잊을지 선택!"

일반 기억 (RNN):
  1걸음 전 ★★★★★  (선명!)
  3걸음 전 ★★★     (흐릿...)
  5걸음 전 ★        (거의 안 보임)
  10걸음 전 ☆       (사라짐!)

LSTM:
  "이건 중요해! 오래 기억하자!"
  → 10걸음 전 갈림길 ★★★★  (아직 기억!)

  "이건 별로야, 잊어도 돼."
  → 3걸음 전 빈 통로   ☆    (버림)

비유: 시험 공부
  일반 기억 = 어제 공부한 건 기억, 일주일 전은 잊음
  LSTM = 중요한 공식은 일주일 전 거도 기억,
         사소한 건 어제 거도 잊음
```

#### 자율주행에 적용하면?

```
LSTM 자율주행:

시점 t=1: "앞으로 직진!" (별다른 정보 없음)
시점 t=5: "오른쪽에 갈림길 발견!" → 기억에 저장!
시점 t=10: "막다른 길이다!"
시점 t=11: "아까 t=5에서 갈림길이 있었지?
           그쪽으로 돌아가자!" ← LSTM이 기억해줌!

일반 DQN이라면:
시점 t=11: "막다른 길이다... 어디로 가지?"
           (갈림길? 기억 안 남...)
```

> 💡 **어렵게 느껴지면 이것만 기억하세요!**
> - RNN = **과거를 기억하는 AI** (하지만 오래된 기억은 잊음)
> - LSTM = RNN의 업그레이드. **중요한 기억은 오래, 사소한 기억은 버림!**
> - 자율주행 예: "이 길은 아까 와본 곳이야, 다른 길로 가자!"

> 🎨 **이 그림을 더 예쁘게 보고 싶다면?** 아래 프롬프트를 Gemini에게 보내보세요!
>
> *프롬프트: "RNN과 LSTM의 차이를 자율주행 자동차에 비유한 다이어그램을 그려줘. 위쪽에 일반 신경망: 자동차가 매 순간 독립적으로 판단(기억 없음). 가운데에 RNN: 자동차가 이전 기억을 다음 단계로 전달(화살표로 연결), 하지만 멀리 갈수록 기억이 흐려짐(색이 옅어짐). 아래쪽에 LSTM: 자동차가 '중요한 기억(갈림길)'은 선명하게 유지하고 '사소한 기억(빈 통로)'은 버리는 모습. 깔끔한 인포그래픽 스타일, 한국어 라벨 포함."*

### 딥러닝 심화: 층이 깊으면 복잡한 판단이 가능하다!

> **이 섹션도 개념만 소개합니다. 실제 코드는 없습니다!**

김선배가 마지막으로 질문했습니다.

"우리 AI의 신경망, 은닉층이 몇 개였죠?"

"1개요. 뉴런 64개짜리."

"맞아요. 1화에서 배운 것처럼, 입력층 → 은닉층 1개 → 출력층. 그런데 만약 은닉층을 **여러 개** 쌓으면 어떻게 될까요?"

```
우리 AI (얕은 신경망):
  입력(11개) → 은닉층 1개(64뉴런) → 출력(3개)

더 깊은 AI:
  입력 → 은닉층 1 → 은닉층 2 → 은닉층 3 → 출력

아주 깊은 AI:
  입력 → 은닉층 1 → 은닉층 2 → ... → 은닉층 100 → 출력
```

이렇게 은닉층을 여러 개 쌓는 것이 바로 **"딥(Deep)"러닝**입니다!

"1화에서 배운 '신경망'에 '깊이'를 더한 것이에요."

#### 왜 깊으면 좋을까?

각 층이 점점 더 **복잡한 개념**을 이해하기 때문입니다.

```
자율주행 예시:

1층 (기초):
  "바로 앞에 벽이 있나?"
  "바로 옆에 벽이 있나?"
  → 단순한 감지!

2층 (조합):
  "앞이랑 옆이 다 벽이면 → 막다른 길이구나!"
  "앞이 뚫리고 옆도 뚫려있으면 → 갈림길이구나!"
  → 1층의 정보를 조합해서 상황을 파악!

3층 (판단):
  "막다른 길인데 뒤로 돌아가면 우회로가 있을까?"
  "이 갈림길에서 어느 쪽이 목적지에 가까울까?"
  → 2층의 상황 파악을 바탕으로 전략적 판단!
```

실생활로 비유하면 이렇습니다:

```
사진 인식 예시 (얼굴 인식):

1층: "밝은 점? 어두운 점?" (픽셀 수준)
2층: "선이 있네! 곡선이 있네!" (윤곽)
3층: "이건 눈이구나! 이건 코구나!" (부분)
4층: "이건 사람 얼굴이다!" (전체)

→ 층이 깊어질수록, 단순한 정보 → 복잡한 개념으로!
→ 이게 바로 "딥(Deep)"러닝의 핵심!
```

"그런데 무작정 깊게 쌓으면 좋은 건 아니에요." 김선배가 덧붙였습니다.

```
층이 너무 깊으면:
  - 학습이 매우 오래 걸림
  - 기울기 소실: 맨 뒤의 수정 신호가 앞까지 전달이 안 됨
    (전화기 게임처럼 중간에 메시지가 사라짐!)
  - 데이터가 적으면 과적합 (v1에서 배운 것!)

→ 적절한 깊이를 찾는 것이 중요!
→ 우리 AI는 은닉층 1~2개면 충분!
```

> 💡 **어렵게 느껴지면 이것만 기억하세요!**
> - 딥러닝 = **은닉층을 여러 개 쌓은 신경망**
> - 층이 깊을수록 = **더 복잡한 패턴**을 이해할 수 있음
> - 1층: "벽이 있나?" → 2층: "막다른 길인가?" → 3층: "우회로가 있나?"
> - 이게 바로 **"딥(Deep)"러닝**이라는 이름의 이유!

```
│  📊 현재 상태 vs 목표                              │
├───────────────────────────────────────────────────┤
│                                                     │
│  현재 (v5): ████████████████████████ 73%            │
│  목표:      ██████████████████████████████ 90%      │
│                                         ↑           │
│                                    이 17%를          │
│                                    채우려면?         │
└───────────────────────────────────────────────────┘
```

### 🤔 왜 73%에서 막혔을까?

v5까지 만들면서 많이 발전했지만, 아직 부족한 것들이 있습니다. 메타코딩은 김선배와 함께 문제를 하나씩 분석했습니다.

### 🔍 부족한 부분 1: 중요한 경험을 충분히 복습하지 않음

메타코딩: "오답 노트에서 랜덤으로 뽑는다고 했잖아요. 근데 **자주 틀리는 어려운 문제를 더 많이 복습**해야 하지 않나요?"

김선배: "맞아요! 지금은 평범한 경험이나 중요한 경험이나 똑같은 확률로 뽑혀요."

```
경험 창고 (현재):
┌──────────────────────────────────────────┐
│ 경험 1: 이동 중 (평범)                    │
│ 경험 2: 이동 중 (평범)                    │
│ 경험 3: 목적지 도달!! (귀하고 중요!)      │ ← 이걸 더 자주
│ 경험 4: 이동 중 (평범)                    │    학습해야 하는데
│ 경험 5: 이동 중 (평범)                    │    랜덤이라 잘 안 뽑힘!
└──────────────────────────────────────────┘
```

**해결책: Prioritized Experience Replay (PER)**

```
중요도 기반으로 뽑기!

┌──────────────────────────────────────────┐
│ 경험 3: 목적지 도달!! (우선순위: ★★★) │ ← 자주 뽑힘!
│ 경험 7: 벽 충돌 (우선순위: ★★)        │ ← 가끔 뽑힘
│ 경험 1: 이동 중 (우선순위: ★)          │ ← 드물게 뽑힘
└──────────────────────────────────────────┘

핵심: "놀라운 경험"을 더 자주 복습!
AI가 예상을 많이 틀린 경험 = 배울 게 많은 경험

기대 효과: +5~8% 성공률 향상!
```

### 🔍 부족한 부분 2: 같은 신경망이 판단도 하고 평가도 함

메타코딩: "또 다른 문제가 있나요?"

김선배: "지금 AI는 '어떤 행동이 좋을까?'를 판단하는 것과 '그 행동이 정말 좋았나?' 평가하는 걸 **같은 신경망**이 해요. 이게 문제예요."

```
현재 DQN 구조:

하나의 신경망 (Policy Network)
  역할 1: "어떤 행동이 좋을까?" (판단)
  역할 2: "그 행동이 얼마나 좋은가?" (평가)

문제:
  자기가 좋다고 한 행동을 자기가 평가?
  → 자기 자신에게 후한 점수를 줄 수밖에 없음!

학교에 비유하면:
  학생이 시험 문제를 내고, 자기가 채점하는 것!
  → 당연히 점수가 높게 나오겠죠?
```

**해결책: Double DQN**

```
개선된 구조:

┌──────────────────┐       ┌──────────────────┐
│ Policy Network   │       │ Target Network   │
│ "어떤 행동이     │ ──▶   │ "그 행동의 가치  │
│  좋을까?" (판단) │       │  는?" (평가)     │
└──────────────────┘       └──────────────────┘

선수가 플레이하고, 심판이 평가!
→ 더 객관적이고 정확한 학습!

기대 효과: +3~5% 성공률 향상!
```

### 🔍 부족한 부분 3: 신경망 구조가 단순함

메타코딩: "그리고요?"

김선배: "지금 신경망은 **'이 위치가 좋은가'** 와 **'이 행동이 좋은가'** 를 구분하지 못해요. 마치 '강남이 좋은 동네인가?'와 '이 집이 좋은가?'를 따로 판단하지 못하는 거예요."

```
현재 신경망:
  입력(11개) → 은닉층(64개) → Q값(3개)

문제: "위치가 좋은 건지 행동이 좋은 건지" 구분 못 함
```

**해결책: Dueling DQN**

```
Dueling DQN 구조:

입력(11개) → 은닉층 ─┬─▶ [상태 가치 V] ─┐
                     │                   ├─▶ Q값(3개)
                     └─▶ [행동 이점 A]  ─┘

V(상태 가치): "이 위치 자체가 얼마나 좋은가?"
  예: 목적지 바로 옆 = 매우 좋은 위치!

A(행동 이점): "직진이 우회전보다 얼마나 나은가?"
  예: 직진 +5, 우회전 -2, 좌회전 -3

Q = V + A
  = "위치가 좋고" + "이 행동도 좋으면" = 높은 Q값!

비유: 부동산
  V = "강남이 좋은 동네인가?" (위치)
  A = "이 집이 같은 동네 다른 집보다 나은가?" (행동)
  → 위치와 선택을 분리해서 판단!

기대 효과: +4~7% 성공률 향상!
```

### 🔍 부족한 부분 4: 학습 맵이 20개뿐

```
현재: 20개 맵으로 학습
문제: 비슷한 패턴만 보다 보니 다양성 부족

해결: 100개 이상의 다양한 맵!

추가할 맵 유형:
┌─────────────────────────────────────┐
│ 미로형: 여러 갈림길 중 하나가 정답   │
│ U자형: 반대 방향으로 먼저 가야 함   │
│ 나선형: 빙글빙글 돌아가야 함        │
│ 열린형: 장애물 거의 없음            │
│ 밀집형: 장애물이 매우 많음          │
└─────────────────────────────────────┘

기대 효과: +3~5% 성공률 향상!
```

### 🔍 부족한 부분 5: AI가 받는 정보가 적음

```
현재 v5 입력 (11개):
  주변 8칸 + 방향 + 목적지 방향

문제: 바로 옆 한 칸만 봄
  → "두 칸 앞에 막다른 길"을 미리 못 봄!

해결: 시야 확장!

개선된 입력 (예시):
┌─────────────────────────────────────┐
│ 주변 1칸 (8개)   ← 현재            │
│ 주변 2칸 (16개)  ← 확장!           │
│ 현재 방향 (1개)                     │
│ 목적지 방향 (2개)                   │
│ 최근 이동 이력 (3개) ← 새로 추가!  │
└─────────────────────────────────────┘

기대 효과: +2~3% 성공률 향상!
```

### 🎯 이 책에서 배운 AI 개념 총정리

```
[기초 개념]
✅ 강화학습 (Reinforcement Learning)
   → 보상과 패널티로 스스로 배우는 AI

✅ DQN (Deep Q-Network)
   → 신경망으로 Q값을 계산하는 알고리즘

✅ Q값 (Q-value)
   → "이 상황에서 이 행동은 미래까지 얼마나 좋은가?"

✅ 상태 벡터 (State Vector)
   → 현재 상황을 숫자 묶음으로 표현한 것 (11개)

✅ 보상 함수 (Reward Function)
   → AI에게 "잘했어/안돼!"를 알려주는 선생님

[AI의 3가지 학습 방식]
✅ 지도학습 (Supervised Learning)
   → 정답을 알려주고 배우는 것 (선생님 있음!)

✅ 비지도학습 (Unsupervised Learning)
   → 정답 없이 패턴을 찾는 것 (선생님 없음!)

✅ 강화학습 (Reinforcement Learning)
   → 시행착오로 배우는 것 (보상과 벌!)

✅ 딥러닝 (Deep Learning)
   → 종류가 아닌 도구! 위 3가지 어디서든 사용 가능한 신경망

[문제 유형]
✅ 회귀 (Regression)
   → 숫자를 예측! "내일 기온은 몇 도?" (선형 회귀: y = ax + b)

✅ 분류 (Classification)
   → 종류를 분류! "이건 고양이? 강아지?" (로지스틱 회귀: Sigmoid)

[신경망 관련]
✅ 신경망 (Neural Network)
   → 입력 → 은닉층 → 출력 (뇌를 수학으로 흉내)

✅ 가중치 (Weight)와 편향 (Bias)
   → 뉴런의 연결 강도. AI가 학습하는 것의 정체!

✅ 활성화 함수 — ReLU
   → 음수는 차단(0), 양수는 통과. 빠르고 효과적!

✅ 활성화 함수 — Sigmoid
   → 0~1 사이로 압축. 확률 표현에 유리!

[학습 원리]
✅ 경사하강법 (Gradient Descent)
   → 오차를 줄이는 방향으로 가중치를 조금씩 수정

✅ 기울기 / 그래디언트 (Gradient)
   → 미분의 결과. "어느 방향으로 수정하면 오차가 줄까?"

✅ 역전파 (Backpropagation)
   → 오차를 뒤에서 앞으로 전파하여 각 가중치 수정

✅ 연쇄법칙 (Chain Rule)
   → 역전파의 수학 원리! 영향을 거꾸로 계산!

✅ 손실 함수 (Loss Function)
   → "AI가 얼마나 틀렸나?"를 수치화한 것

✅ 로컬 미니마 (Local Minima)
   → 가짜 최저점. 더 낮은 곳이 있는데 여기서 멈춤

✅ Learning Rate (학습률)
   → 한 걸음의 크기. 크면 빠르지만 불안정, 작으면 안정적이지만 느림

✅ Learning Rate Scheduling
   → 처음엔 크게, 나중엔 작게. 효율적 학습!

✅ 옵티마이저 — Adam
   → SGD의 업그레이드! 상황에 맞춰 보폭 자동 조절 (프로 스키어)

✅ Gradient Clipping
   → 한 번에 너무 크게 변하지 않도록 기울기를 제한

[데이터 처리와 평가]
✅ 전처리 (Preprocessing)
   → 세상의 정보를 AI가 이해할 수 있는 숫자로 변환!

✅ 정규화 (Normalization)
   → 값들의 크기를 비슷한 범위로 맞추기 (-1~+1)

✅ 과적합 (Overfitting)
   → 연습 문제만 잘 풀고, 새 문제는 못 푸는 현상

✅ 일반화 (Generalization)
   → 처음 보는 상황에서도 잘 작동하는 진짜 실력

✅ 훈련셋 / 테스트셋
   → 공부용 문제와 시험 문제는 반드시 분리!

✅ 정확도 (Accuracy)
   → "성공률"의 AI 용어! 100번 중 73번 성공 = 73%

✅ 교차검증 (Cross-Validation)
   → 시험지를 여러 개 만들어 돌아가며 시험보고 평균!

[과적합 방지 기법]
✅ L2 규제 (Weight Decay)
   → 가중치 크기 제한 (한 과목 100점보다 전 과목 80점!)

[학습 단위]
✅ 에피소드 (Episode) → 시작~종료까지 한 판
✅ 에포크 (Epoch) → 전체 데이터 한 바퀴
✅ 이터레이션 (Iteration) → 미니배치 하나 학습

[탐험과 전략]
✅ Epsilon-Greedy (탐험 vs 활용)
   → 처음엔 탐험 많이, 나중엔 배운 것 활용

✅ 경험 리플레이 (Experience Replay)
   → 과거 경험을 저장하고 랜덤으로 복습

✅ 미니배치 (Mini-batch)
   → 한 번에 32개씩 뽑아서 학습 (안정성 + 속도)

[추론 최적화]
✅ 학습 vs 추론
   → 학습은 한 번(오래 걸려도 됨), 추론은 매번(빨라야 함)

✅ 캐싱 (Caching)
   → 성공 경험 저장으로 추론 속도 향상

✅ Policy > Cache 원칙
   → 실시간 판단이 저장된 기억보다 우선!

[번외편에서 배운 것]
✅ 의사결정 트리 (Decision Tree)
   → 질문으로 판단! 해석 가능한 AI (지도학습)

✅ 랜덤 포레스트 (Random Forest) / 앙상블 (Ensemble)
   → 트리 100개가 투표! 다수결의 힘! (지도학습)

📚 LSTM/RNN (순환 신경망) — 개념만
   → 과거를 기억하는 AI. 중요한 기억은 오래!

📚 딥러닝 심화 — 개념만
   → 층이 깊을수록 복잡한 패턴 이해! (딥 = 깊은)

[고급 기법 (미리보기)]
✅ Double DQN → 판단과 평가를 분리
✅ Dueling DQN → 위치 가치와 행동 이점을 분리
✅ Prioritized Experience Replay → 중요한 경험을 자주 복습
```

### 💡 메타코딩이 진짜 배운 것

기술적인 것 말고, 이번 프로젝트에서 진짜 깨달은 것들이 있었습니다.

**첫째: 실패가 교과서다**

v1의 실패가 없었다면 과적합을 몰랐을 것입니다. v2의 착각이 없었다면 훈련셋/테스트셋 분리를 지나쳤을 것입니다. 모든 실패가 다음 버전을 만드는 재료가 됐습니다. AI도 실패에서 배우고, 개발자도 실패에서 배웁니다.

**둘째: 한 번에 완벽할 필요 없다**

```
v0 → v1 → v2 → v3 → v4 → v5 → ...

처음부터 v5를 만들려고 했다면?
→ 너무 복잡해서 포기했을 것

한 번에 하나씩 문제를 해결하면?
→ 결국 v5까지 도달!
```

이것은 AI의 학습 방식과도 똑같습니다. AI도 한 번에 완벽해지지 않습니다. 수천 번의 에피소드를 거치면서 **조금씩, 조금씩** 나아지죠.

**셋째: "왜?"를 알면 "어떻게?"가 보인다**

73%가 왜 나왔는지 이해했더니, 어떻게 90%로 올릴 수 있는지 자연스럽게 보였습니다. 문제의 원인을 아는 것이 해결의 시작입니다.

## ✅ 이해도 체크리스트

### AI의 큰 그림 (프롤로그)

- [ ] 지도학습, 비지도학습, 강화학습의 차이를 설명할 수 있다
- [ ] 딥러닝이 별도의 종류가 아니라 "도구"라는 것을 알겠다
- [ ] 회귀와 분류의 차이를 알겠다
- [ ] 선형 회귀(y = ax + b)가 무엇인지 이해했다
- [ ] 로지스틱 회귀(Sigmoid)가 확률로 분류하는 것임을 알겠다

### 기본 개념 (0화~1화)

- [ ] if 규칙의 한계(국소 최적화)를 설명할 수 있다
- [ ] 강화학습이 왜 필요한지 알겠다
- [ ] Q값이 무엇인지 한 문장으로 말할 수 있다
- [ ] 신경망의 입력-은닉-출력 구조를 알겠다
- [ ] 뉴런 하나가 어떻게 계산하는지 이해했다
- [ ] 전처리(Preprocessing)가 왜 필요한지 알겠다
- [ ] 정규화(Normalization)가 왜 필요한지 알겠다

### 활성화 함수와 학습 (1화~2화)

- [ ] ReLU가 하는 일을 알겠다
- [ ] Sigmoid가 하는 일을 알겠다
- [ ] 경사하강법을 산 비유로 설명할 수 있다
- [ ] Gradient(기울기)가 미분이라는 것을 이해했다
- [ ] 역전파가 왜 필요한지 알겠다
- [ ] 연쇄법칙(Chain Rule)이 역전파의 원리라는 것을 알겠다
- [ ] 로컬 미니마가 뭔지 이해했다
- [ ] 에피소드, 에포크, 이터레이션의 차이를 알겠다

### 데이터와 학습 전략 (3화)

- [ ] 훈련셋과 테스트셋을 왜 분리하는지 알겠다
- [ ] 과적합이 왜 위험한지 이해했다
- [ ] 정확도(Accuracy) = 성공률이라는 것을 알겠다
- [ ] 교차검증이 왜 더 정확한 평가인지 이해했다
- [ ] L2 규제의 개념을 알겠다
- [ ] Exploration vs Exploitation을 이해했다
- [ ] 경험 리플레이가 왜 필요한지 알겠다

### 최적화와 실무 (4화~5화)

- [ ] Learning Rate Scheduling의 원리를 안다
- [ ] Adam 옵티마이저가 SGD보다 나은 이유를 알겠다
- [ ] Learning Rate가 학습에 미치는 영향을 안다
- [ ] 학습과 추론의 차이를 알겠다
- [ ] Policy > Cache 원칙을 이해했다

### 번외편 (v6)

- [ ] 의사결정 트리가 "질문"으로 판단하는 AI라는 것을 알겠다
- [ ] 랜덤 포레스트가 "투표"로 정확도를 높인다는 것을 알겠다
- [ ] LSTM이 과거를 기억하는 AI라는 것을 알겠다
- [ ] 문제에 맞는 AI를 고르는 것이 중요하다는 것을 알겠다
